# FLOW-02/06/09 — подтверждение записи анонимных HTML-агрегатов

Владелец — `tor-traffic_behavior`; F получает его ограниченный read-only отчёт
через web composition. Этот пакет дополняет `flow-observation-hours-v1.md` и
`flow-data-signals-v1.md`. Персональных событий, согласий, IP, cookie, URL и
читательских идентификаторов нет. Epoch обозначает запуск серверного обработчика.

## Какое свидетельство сохраняется

Наличие строки `ril_flow_observed_hourly` говорит только о сохранённых ответах.
Оно не доказывает непрерывность сбора в течение часа. Локальный пустой успешный
цикл, ноль потерь нового процесса и все 24 строки также не доказывают качество
предыдущего периода.

`ril_flow_health_epochs` хранит начало, подтверждённую границу, срок аренды,
поколение, ожидаемую границу и накопленные числовые счётчики потерь/ошибок.
`ril_flow_health_hourly` хранит только признаки потерь и ошибок по часам. Счётчики
одного процесса продолжают показываться отдельно; их нельзя делить на общий
отчёт и называть долей охвата.

Один цикл существующего RIL pump:

1. Получает ограниченную аренду и DB-clock checkpoint. Соединение освобождается.
2. Ставит FIFO-барьер в существующую очередь. Неблокирующий `try_lock` удерживается
   только во время постановки; SQL и ожидания ответа под ним нет. HTTP использует
   тот же краткий барьер вокруг часов и `try_send`, поэтому приостановленный
   producer не может оказаться за подтверждённым барьером.
3. Сохраняет обычный неизменяемый RIL UUID и дожидается `status=done` именно этого
   пакета. Четыре materialization за проход — прежняя ограниченная работа.
   Успешный enqueue ещё не подтверждает запись итогов. Пустой drain — отдельный
   упорядоченный ответ очереди, после которого тоже требуется SQL ACK.
4. В одной SQL-транзакции проверяет epoch, поколение, живую аренду, DB clock,
   `done` пакета и его discarded receipt. Только затем продвигает границу.

Потери и ошибки сохраняются независимо от ожидания `done`: известный отказ
записи не исчезает после перезапуска. Поскольку точное время каждой потери не
хранится, признаки консервативно помечают пересекающиеся часы, включая граничный
час округлённой миллисекунды. Эти признаки — не точное число потерянных ответов.

## Часы, остановка и отсутствие измерения

Аренда — 30 секунд; producer дополнительно прекращает HTML-сбор по монотонным
часам через 25 секунд. Технический RIL и основной HTTP-ответ продолжают работать.
Часы ответа проверяются относительно DB-clock аренды с пределом 2 секунды;
отклонение даёт потерю измерения, а не выдуманное время. Подтверждённая граница
отстаёт от DB cut на эти 2 секунды. Будущий допустимый producer поэтому не
добавляет ответ в уже подтверждённый час.

Ожидание пакета продлевает только живую аренду, не подтверждённую границу.
Максимальный возраст checkpoint — 120 секунд. Истёкший epoch не возобновляется:
он окончательно retire, сохраняя неизвестный хвост. Новый epoch не заполняет
старый интервал. Прямой `shutdown` сначала закрывает producer и затем retire;
abort/SIGTERM закрывает producer через `Drop`, оставляя непроверенный хвост
аренды неизвестным. Durable RIL-пакеты по-прежнему доступны другому pump для
штатного точного повтора.

История до этого журнала не восстанавливается. Отказ readiness старой схемы
закрывает управляемый HTML-сбор, сохраняя технический RIL. Новая схема требуется
для нового подтверждения качества; отсутствие таблиц не выдаётся за здоровый ноль.

## Периодный отчёт и административный путь

`PgFlowAudience::observed_health_report(days, zone)` читает HTML-числа и health в
одной `REPEATABLE READ READ ONLY` транзакции. У них одинаковая UTC-граница и
снимок. Более поздний ACK не может удостоверить числа из более раннего снимка.
Допустимы 1/7/30/90 дней, два соседних окна завершённых часов, максимум 4320 часов.
Часовой пояс БД не меняет UTC-границу; выбранная зона меняет только отображение.

Час подтверждён, когда объединение интервалов покрывает его целиком **и каждый
зарегистрированный исполнитель**, пересекающий час, подтвердил свою часть.
Один чистый исполнитель не скрывает незавершённый хвост другого. Это свидетельство
данного механизма зарегистрированных исполнителей; не полнота всех процессов
установки, не число людей и не измерение запросов, не дошедших до приложения.

«Аудитория» показывает отдельно подтверждённые часы, часы с потерями и часы с
ошибками для обоих окон. Локальные счётчики сохраняют подпись своего ограничения.
GET не создаёт ACK и не меняет состояния; недоступный журнал даёт 503 и явное
отсутствие диагностики. Сохраняются живая роль администратора, private/no-store,
noindex и формы без JavaScript. SQL — 750 ms, lock timeout — 75 ms; общий HTTP
предел — 950 ms. Цикл pump ограничен 6 секундами, операции health — 950 ms,
пауза между циклами — 10 секунд. Соединения не удерживаются при ожидании очереди.

`html_quality` и `html_change` используют долговечные подтверждённые часы вместо
количества строк. Потери/ошибки любого сравниваемого окна запрещают сравнение.
Полностью подтверждённый пустой интервал может дать известный ноль сохранённых
ответов; неполный или потерянный интервал — нет. Unknown не завершает старый
эпизод. Предыдущие пороги изменения относятся только к сохранённым ответам.

Удержание health — 181 день, покрывающее два 90-дневных окна. Очистка за проход
не больше 500 часовых строк и 100 старых epoch. Возврат долго отсутствовавшего
процесса ограниченно помечает только удерживаемое окно, не расширяет историю.

## Предметная проверка

PostgreSQL проверяет ожидание именно материализованного пакета, пустой ACK,
конкурентный повтор, новое поколение, истёкшую аренду, прежний отказ после нового
процесса, 48 часов с потерянным вторым исполнителем, последнюю миллисекунду часа,
UTC при `Asia/Kathmandu`, реальную блокировку materialization, повтор и shutdown.
HTTP проверяет read-only и ограниченный 503 при блокировке health-таблицы.
Браузер проверяет действительную страницу и диагностический блок на 390/1440.
Эти локальные результаты не заменяют CI и post-merge на окончательной ревизии.
