# TOR — I-09: сравнение времени проверок без потери покрытия

Программа `tools/ci_metrics.py` читает реальные задания GitHub Actions. Это
не расчёт стоимости GitHub и не подтверждение ускорения по одной паре запусков.
Нормативные требования: [I-07/I-09](../roadmap/lanes/I.md) и
[исходный сценарий S062](https://app.notion.com/p/40432a84beec81a18573cc73a6db3ece).

## Как сравнивать

```bash
# Нужен токен только для чтения GitHub Actions (если лимита анонимного API недостаточно).
export GITHUB_TOKEN="<read-only token>"
python3 tools/ci_metrics.py \
  --before-sha 84de2427385dae3f23b5a60fec84e77ad068ef07 \
  --sha db96208ff5179e32fac24a8c08173e87b3741828 \
  --json
```

`comparison` формируется **только** при выполнении всех условий:

- Оба набора относятся к одному типу события GitHub
  (`push`, `pull_request` либо ручной запуск).
- Все процессы и реальные задания **успешно завершены**.
- Список рабочих процессов совпадает; ни один не представлен дважды.
- Совпадает поимённый список **фактически исполненных** заданий.
- Нет пропущенных заданий; пропуск основной проверки при зелёной оболочке
  не считается ускорением.
- Данные содержат действительные временные метки; неполная выдача API
  вызывает отказ.

Если хотя бы одно условие нарушено, `comparison=null`, а
`comparison_blocker` объясняет причину. Программа завершится ненулевым
кодом, но отдельные измерения останутся видны. Выбор I-07 на PR может
корректно пропускать дорогие задания: их **меньшее время само по себе не
доказывает ускорения при том же покрытии**.

## Фактический замер двух завершённых `main` (29.10.2026)

Сверено по GitHub API: 15 успешных рабочих процессов и 29 успешно
исполненных заданий на **каждом** SHA. Тип события: `push`, пропусков нет.
Списки всех 29 имён заданий совпадают.

| --- | ---: | ---: |
| Успешных процессов / заданий | 15 / 29 | 15 / 29 |
| Медиана ожидания задания | 3 с | 64 с |
| 95-й процентиль ожидания | 4 с | 441,4 с |
| Медиана исполнения задания | 13 с | 12 с |
| 95-й процентиль исполнения | 172,6 с | 189,2 с |
| Сумма времени исполнения | 22,65 мин | 26,55 мин |

Сумма выросла на **3,90 мин (+17,2%)**, а время ожидания стало значительно
больше. Это наблюдение, **не доказательство**, что изменение селектора
замедлило TOR: код коммитов и загрузка исполнителей GitHub были разными.
Сумма времени задания — не стоимость счёта GitHub. Для оценки устойчивого
эффекта нужны повторные сопоставимые прогоны на равных изменениях и
подтверждённая сохранность обязательного покрытия.

## Граница результата

I-09 получила сравнимую базу и защиту от ложного ускорения при
пропущенных заданиях. Сокращение времени или стоимости **не доказано**.
I-06 (административная защита `main`) и I-10/I-11 (отдельный стенд)
отложены, но эта работа не зависит от них и не изменяет VPS.
