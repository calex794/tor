# G-09 — административная сверка приватного S3 и PostgreSQL

Статус: безопасный диагностический интерфейс из [#748](https://github.com/calex794/tor/issues/748). **Не** механизм очистки, не runbook изменения базы, не запущенный планировщик.

## Доступ

В сборке с `tor-web --features s3-paid` и работающей авторизацией сайт не открывает операторский интерфейс автоматически. Его отдельно включает `TOR_G09_OPERATOR_ENABLED=1`, только при заранее корректной конфигурации приватного `TOR_PAID_S3_BUCKET` и AWS credentials существующего частного S3. Не устанавливать флаг в demo, не объявлять публичный S3 bucket. Не передавать bucket, endpoint, ключ, токены или объектный путь из браузера.

После включения администратор с активной сессией получает ссылку **Аудит S3** в кабинете. Маршрут `GET /admin/storage/reconciliation` проверяет администратора по действующей сессии на каждый запрос. На странице не отображается имя бакета, пути, URL, содержимое глав или криптографические ключи. Все ответы `no-store`, `noindex`, CSP без сторонних ресурсов.

Каждая операция выполняется только через `POST /admin/storage/reconciliation/run` с Origin и CSRF. Действие записывается в `g09_operator_requests` **до** вызова S3. Если запись аудита не прошла, операция не начинается.

## Кнопки и ограничения

| Действие | Когда допустимо | Фактическая работа |
|---|---|---|
| Обработать одну порцию | Цикл ещё не завершён, lease свободна | S3 → PG: ≤1000 ключей LIST; PG → S3: ≤128 HEAD |
| Начать новый цикл | Только предыдущий цикл завершён | Увеличивает номер цикла, обнуляет счётчики/курсор; результаты предыдущего цикла сохраняются |
| Разрешить повтор | Только остановленная обратная PG → S3 проверка | Сбрасывает флаг остановки и счётчик подряд идущих ошибок; предыдущие данные сохраняются |

Направления и области жёстко определены кодом: `chapter`, `chapter_asset`, два допустимых набора операций. Нельзя выбрать cover/CDN, префикс, S3 endpoint или отдельный объект. Одновременно два обходчика не продвигают один checkpoint: PostgreSQL lease/epoch и фензинг. Ни одна кнопка не удаляет и не загружает содержимое.

## Чтение сигналов

- **Кандидаты без реестра**: S3→PG, физический файл без регистрации и после grace. Не удалять: сперва вручную проверить закреплённые редакции, исторические ссылки, незавершённый upload и возможное восстановление.
- **Отсутствующие с ссылками**: PG→S3, подтверждённый ответ HEAD 404 для объекта, привязанного к действующей редакции/изображению. Сверить с резервной копией/репликацией, инициировать отдельное контролируемое восстановление. Не удалять строку PostgreSQL.
- **Несовпадение метаданных**: HEAD не согласуется по размеру, MIME или заявленному SHA-256. HEAD не доказывает равенство реальных байтов; требуется отдельный контролируемый GET и хеширование.
- **Неизвестно / ошибки / остановлено**: отсутствие доступа, 403/5xx, таймауты либо неполный список. Это не подтверждение пропажи файла. После восьми подряд неудач обратный сканер останавливается до действий администратора.
- **Покрытие**: в PG→S3 снимок `scanned / expected`, при новом сканировании может устареть, пока создаются новые записи. Для S3→PG полнота определяется финальным continuation_token.

## Границы и проверка

Рабочие миграции не применяются в рамках разработки. Ни деплой, ни изменение AWS-политик, ни cron/systemd, ни автоматическое S3 DELETE не разрешены. Оператору нельзя принимать решение о безвозвратном удалении купленной V1 только по статусу одного скана.

В CI проверять PostgreSQL 18, настоящий loopback MinIO, HTTP-администратора/пользователя/отсутствия сессии, отказ cross-origin/CSRF, запрет произвольного scope и повторяемость нового цикла. Исполнять только на одноразовой `tor_ci`.

Плановый bounded worker, фактическая GET/SHA проверка, ручное восстановление и отдельные источники истины для cover/CDN — последующие срезы #748.
