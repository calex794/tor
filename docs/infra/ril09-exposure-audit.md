# TOR — RIL-09: проверка внешней публикации и отпечаток маршрутов

**Область:** системный Nginx на отдельном TOR VPS `pandaolate.ru`, Rust/Axum за `127.0.0.1:3000`. Проект обслуживает анонимные страницы и приватные страницы с проверкой сеанса; нельзя запрещать весь префикс `/me` на Nginx, потому что сервер должен вернуть редирект на вход, а приложение — применить собственные права. Эта проверка не подменяет RIL-08 и не вводит автоматические блокировки.

## Уровни доказательств

1. **CI репозитория:** `python3 tools/check_ril_exposure.py` строит постоянный SHA256-отпечаток конечного `method + template + source + handler + policy`, проверяет привязку systemd к loopback, включённую авторизацию и что персональный анализ не включается образцом службы. Проверки мутаций — `tests/architecture/test_ril_exposure.py`. **Это только предполагаемая конфигурация, не сведения о запущенном VPS.**
2. **Реальный VPS (только чтение):** на локальной проверенной копии TOR запустить от root `bash ops/audit-ril-exposure-vps.sh`. Скрипт не перезагружает Nginx и не изменяет файлы, базу, правила сети или службу. Он читает `nginx -T` во временный файл с правами 0600, сверяет сервер `pandaolate.ru` (HTTPS 443, локальный upstream, отсутствие `autoindex`, внешнего `stub_status`, опасных `alias` и открытого HTTP-проксирования), затем делает **только GET-запросы без cookie** к корню, `/me`, закрытому API чтения, `/admin`, `/internal/metrics` и `/.env`. Тело ответа не сохраняет. Выход — только коды и безопасный SHA256.
3. **Приёмка:** статус `RIL09_AUDIT_OK`, `nginx_config_reviewed=true` и `public_origin_reviewed=true`, `findings_count=0`, подтверждённые SHA приложения и проверяемой рабочей копии, и отдельная проверка прав/CSRF/owner на PostgreSQL. **Не считать RIL-09 полностью проверенным по одной успешной CI.**

## Безопасный запуск

На VPS использовать закреплённую подтверждённую ревизию репозитория (не скачивать произвольную версию `main` перед проверкой), не публиковать командный вывод `nginx -T`, приватные ключи, файлы `/etc/tor`, cookie и URL с подписанными параметрами. Результат с отпечатком и числом проверок можно записать в Tela. Скрипт не делает `nginx -s reload`, `systemctl restart`, SQL или сетевые POST. Он заканчивает работу с ошибкой при отсутствии доступа/данных, неизвестном TLS-сервере, неразрешённом внешнем маршруте либо небезопасном проксировании.

**Ограничения статического анализатора:** Nginx поддерживает переменные, `include`, регулярные выражения и условную маршрутизацию; здесь проверяется уже раскрытый `nginx -T`, однако для сложной конфигурации и ошибочной системы разрешений нужен отдельный ручной осмотр. Финальную защиту приватных маршрутов применяет Auth/Axum, не RIL. Без доступа к VPS нельзя подтвердить реальное внешнее состояние; не заявлять о завершённой эксплуатации.
