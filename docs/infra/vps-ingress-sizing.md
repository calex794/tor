# TOR — внешний VPS, домашние Rust и PostgreSQL 18

**Решение 31.10.2026:** VPS — только публичный вход Nginx/HTTPS и WireGuard, домашний сервер — TOR/Rust и PostgreSQL 18 на локальном SSD. Объекты S3 по возможности выдаются браузеру напрямую, по правилам доступа. Пока только разработка в GitHub Actions; на серверы ничего не раскатывать.

## Размер внешнего узла

Начальный кандидат: 1 vCPU, 1 ГБ RAM, 15 ГБ SSD, публичный IPv4, канал 100 Мбит/с, доступный UDP для WireGuard, 80/443 TCP для HTTPS. Ценовой ориентир FirstVDS «Прогрев NVMe» — 339 ₽/мес. по опубликованному прейскуранту от 07.09.2026; перед заказом проверить тариф, трафик, защиту от DDoS и условия провайдера. Источник: https://firstvds.ru/docs/tariffs.html .

Условия расширения: сначала измерить загрузку CPU и памяти от Nginx и WireGuard. Если упираемся в процессор — 2 vCPU; если в память — 2 ГБ. Более дорогой VPS не устранит недостаточную исходящую скорость дома.

## Лабораторная проверка

Workflow: `.github/workflows/tor-vps-ingress.yml`; сценарий: `tests/load/vps_ingress_ci.sh`; локальный HTTP-источник: `tests/load/vps_ingress_backend.py`.

GitHub Actions создаёт три отдельные временные сетевые среды: читатель → Nginx/VPS → WireGuard → домашний HTTP-источник. Ключи одноразовые. Проверяется шифрованный маршрут, правильное перезаписывание пользовательских заголовков IP и скорость для ответов 4, 64 и 256 КиБ. Ограничивается канал VPS до 100 Мбит/с, исходящий канал дома до 20, 50 и 100 Мбит/с. Результаты `wrk`, параметры WireGuard и сетевые счётчики сохраняются на 14 дней.

**Ограничения:** общий процессор исполнителя GitHub, нет реального внешнего соединения, TLS, домашнего провайдера, PostgreSQL и TOR. Значит, результаты проверяют лабораторную топологию, а не доказывают предел реального VPS.

При ответе 64 КиБ математический предел одной только исходящей полосы: 20 Мбит/с ≈38 ответов/с; 50 Мбит/с ≈95/с; 100 Мбит/с ≈191/с. Реальные пределы ниже из-за заголовков, шифрования, конкуренции запросов, задержек и кода сайта.

## Безопасность

На VPS наружу только 80/443 TCP и порт WireGuard UDP. Из дома устанавливается исходящее защищённое соединение. У домашнего HTTP-приёмника только адрес интерфейса туннеля, TOR за ним; PostgreSQL только localhost:5432. Нельзя доверять входящим `X-Forwarded-For`; публичный Nginx перезаписывает его фактическим адресом. Приватные страницы, токены и ссылки S3 запрещено складывать в общий кэш или журналы.

**Следующий шаг:** дождаться CI с конкретным SHA и проверить журнал; затем отдельно измерить на реальной связке домашняя исходящая скорость → VPS, прежде чем утверждать пропускную способность.
## Дополнительная проверка устойчивости (PR №350)

В лабораторный сценарий добавлены: инициирование WireGuard именно домашним узлом (VPS узнаёт его текущий адрес), невозможность прямого обращения к домашнему HTTP по внешнему сетевому адресу, обрыв WireGuard с ожидаемым кодом 502/504, восстановление соединения, отказ доверять подставленным клиентом заголовкам Forwarded и X-Forwarded-*, а также отдельные испытания HTTPS на самоподписанном однодневном сертификате.

Во время HTTP/HTTPS-замеров сохраняются отдельные счётчики общей загрузки процессора `mpstat` и процессов Nginx `pidstat`. Общий исполнитель GitHub Actions **не эквивалентен** VPS с одним виртуальным ядром, поэтому не следует считать эти цифры паспортной производительностью выбранного тарифа. Услуги на настоящих серверах не изменялись.

Для рабочей системы сертификат должен быть доверенным, с автоматическим продлением; HTTP должен переадресовываться на HTTPS, реальные 80/443 должны проходить через защищённую конфигурацию. Эти параметры не воспроизводятся лабораторным однодневным сертификатом.
