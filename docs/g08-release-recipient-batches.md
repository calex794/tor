# G-08 — выборка подписчиков новых глав

C-16 уже содержит каноническое представление reader_followed_release_candidates, обеспечивающее явную подписку и проверку первого выпуска (не редактирования). Новый PgReleaseRecipients использует ровно эту выборку для одной главы.

Выборка идёт пачками по 100 через user_id > cursor, без OFFSET и без глобального ограничения: 201 подписчик даёт страницы 100+100+1. Модель раскрывает только идентификатор читателя, книги, главы, вид платного доступа и цену, но не текст главы. Просмотренное уведомление не считается отпиской. Скрытые и заблокированные главы не попадают в выдачу, платные — только после прикрепления проверенного защищённого объекта.

Это только кандидаты, НЕ отправка сообщений и НЕ согласие на внешний канал. Перед реальной отправкой нужны повторная проверка подписки, отдельное согласие пользователя (C-17, PR #283), защита от повторов и индивидуальные квитанции (G-06/G-07, PR #277). Нет транспорта, рабочего обработчика событий или чекпоинта; в рабочую БД миграций не добавлено.

Проверка в одноразовой PostgreSQL 18: cargo test -p tor-ingest --test release_recipient_batches_pg -- --ignored --test-threads=1. Сценарии: 201 читатель, 101-й и 201-й, повтор страницы, отметка прочтения, отписка, поздняя подписка, блокировка книги/главы, новая редакция и подтверждённая платная глава.
