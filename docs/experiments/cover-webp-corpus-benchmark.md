# G-05c — WebP q85 cover corpus benchmark

**Offline only; no S3 access, VPS deployment, database, migrations or automatic backfill.**

After the v2 lossy WebP recipe (#1017) and the G-05b read-only metadata inventory,
the next required evidence is **representative cover quality and encoder cost**.
A single attractive book cover does not establish an average saving for 100,000 books.

## Run

Use 50–100 **different, legitimately available original** cover files in one
local folder. The example accepts only PNG, JPEG and WebP sources within TOR's
8-MiB input limit. It applies the exact `tor-ingest` Rust processing pipeline,
rather than Pillow or a separate approximation.

```sh
cargo run --release -p tor-ingest --example cover_codec_bench -- \
  /local/cover-sample 100 /tmp/cover-previews > /tmp/cover-corpus.csv
```

The first argument is a flat source directory, the optional second is the
maximum number of **unique** valid covers to process (default 100, max 500),
and the optional third is a directory for locally saved v1/v2 WebP previews.

- Inputs are opened read-only and never modified.
- Results are written to stdout as CSV; summary and failures go to stderr.
- Identifiers are truncated source SHA-256 values, not paths, titles or owners.
- Output images go **only** to the optional local preview directory.
- No encoder selection changes, no network calls, no S3 keys or credentials.
- Results include both 380x570 main and 150x220 card, including fallback to
  lossless for transparent sources, as the actual v2 recipe does.

## CSV columns

- `source_sha12` — 12 hexadecimal characters derived from the source, to pair main/card.
- `variant` — main or card.
- `legacy_bytes`, `lossy_bytes`, `saving_percent` — true output byte lengths for the two
  Rust recipes. Negative savings are allowed.
- `legacy_pipeline_ms`, `lossy_pipeline_ms` — elapsed local time for *both*
  outputs, including source decoding and resizing. These are repeated in each
  variant's CSV row. Do **not** sum them across main/card, or claim this is
  production VPS throughput.
- `psnr_vs_lossless_db` — decoded RGBA pixel PSNR comparing v2 to the
  same resized image generated by the existing v1. Infinite means identical.
  It is not a text readability score.
- `v2_encoding` — either `webp-lossy-q85` or `webp-lossless`.

## Acceptance gate

Before changing production defaults or building re-encoding for historical
covers, require:

1. 50–100 **book** covers with varied typography, contrast, gradients,
   illustration styles and source dimensions; video/slide thumbnails do not
   count toward the book sample.
2. Report median, 10th/90th percentile, worst regressions, aggregate savings
   and max CPU/elapsed costs separately for main and card.
3. Blind or side-by-side review of the **text at the actual 150x220 card size**,
   with failures described, not just PSNR. Check all negative-savings samples.
4. Measure the worker under realistic concurrency/CPU constraints; local
   benchmark time only establishes relative cost.
5. Use G-05b inventory to estimate actual billable storage impact, keeping
   originals, historical copies and CDN traffic distinct.

Even after quality acceptance, **never overwrite** old immutable S3 objects.
A backfill needs its own approval/CAS and CDN-safe promotion process.

## Test

```sh
cargo test -p tor-ingest --all-targets
cargo clippy -p tor-ingest --all-targets -- -D warnings
```

These compile and exercise the example's basic PSNR and MIME helper tests.
