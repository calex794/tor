# Разработка в девяти направлениях

## Общий старт
Точка S0: единые контракты, исходные SHA, владельцы таблиц и файлов, действующая PostgreSQL и минимальный реальный браузерный сценарий.

| Линия | Базовое имя |
|---|---|
| A — аккаунты | `lane/a-identity` |
| B — публикация | `lane/b-publishing` |
| C — чтение | `lane/c-reading` |
| D — покупки | `lane/d-commerce` |
| E — сообщество | `lane/e-community` |

| G — импорт | `lane/g-ingest` |
| H — интерфейс | `lane/h-interface` |

Изменения вести в ветках `feat/<lane>/<scenario-or-slice>` от свежего `main`: **внутри ветки закончить одну предметную операцию целиком**, провести её пакет тестов, исправить падения группами, повторить обязательный пакет и лишь затем открыть PR. Ветки `lane/*` — только координация, не место накопления девяти гигантских слияний. См. [исполнительский роадмап](roadmap/README.md), [тестовый протокол](roadmap/tests-and-handoffs.md).

## Очередь объединения
1. Исполнитель создаёт модуль/маршрут и тесты только своей области.
2. PR указывает сценарий S-ID, изменения контракта, границы данных и доказательства.
3. CI выполняет нужные проверки (не отключать доменные PG и сквозные тесты, если изменены права/деньги).
4. Интегратор I проверяет основание PR против текущего main, при необходимости повторяет CI; только затем вливает.
5. Из проверенного main вручную формируется кандидат на сервере; активация требует точного 40-символьного SHA, проверки схемы PostgreSQL и успешной проверки отката. Само слияние PR не меняет VPS.
6. Соответствие NEwBOO подтверждается независимыми браузерными/HTTP/PG проверками, затем отмечается в единой матрице Notion.
