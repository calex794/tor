Ветки `lane/*` — только координация, не место накопления девяти гигантских слияний. См. [исполнительский роадмап](roadmap/README.md), [тестовый протокол](roadmap/tests-and-handoffs.md).

## Очередь объединения
1. Исполнитель создаёт модуль/маршрут и тесты только своей области.
2. PR указывает сценарий S-ID, изменения контракта, границы данных и доказательства.
3. CI выполняет нужные проверки (не отключать доменные PG и сквозные тесты, если изменены права/деньги).
4. Интегратор I проверяет основание PR против текущего main, при необходимости повторяет CI; только затем вливает.
5. Из проверенного main вручную формируется кандидат на сервере; активация требует точного 40-символьного SHA, проверки схемы PostgreSQL и успешной проверки отката. Само слияние PR не меняет VPS.
6. Соответствие NEwBOO подтверждается независимыми браузерными/HTTP/PG проверками, затем отмечается в единой матрице Notion.

## Отказ DNS зеркал Ubuntu в браузерном CI

На GitHub Actions с Ubuntu 24.04 перед прежней установкой Playwright вызывается
`tools/ci_prepare_ubuntu_mirror.sh`. Если хотя бы одно из трёх штатных имён
Ubuntu разрешается, helper сохраняет текущий список зеркал. При отказе всех трёх
он проверяет HTTPS-метаданные четырёх Noble suites штатным Ubuntu archive keyring,
сверяет Suite и добавляет Kernel.org с приоритетом 0 перед существующими зеркалами.
Приоритет отделяется TAB согласно [APT Noble](https://manpages.ubuntu.com/manpages/noble/man1/apt-transport-mirror.1.html).

Заменяется только список зеркал одноразового runner. Suites, components, Signed-By,
обычная проверка подписей, хешей и сроков APT сохраняются. Собственные ключи, заданные
IP, отключение TLS или проверки подписей не используются. У community mirror
возможна задержка синхронизации; это резерв после подтверждённого DNS-отказа.

Версия Playwright 1.56.1, полный `--with-deps`, шрифты и все браузерные задания
сохранены. [Исходная диагностика](https://github.com/calex794/tor/actions/runs/43038921078)
показала отказ только трёх проверяемых Ubuntu-имён при работающих контрольных DNS.
[Реальная проверка установки](https://github.com/calex794/tor/actions/runs/43039701135)
подтвердила подписи четырёх suites, неизменность sources/keyring, идемпотентность,
полную установку зависимостей и запуск headless-shell и полного Chromium.
Это проверка установки; полная прикладная приёмка остаётся в обычном Integration CI.
