# tor → испытательный сервер

## Предлагаемое развёртывание
`GitHub main` → CI Rust + PostgreSQL + браузер → собранный артефакт/образ → отдельная тестовая среда → HTTPS-прокси → видимый сайт.

1. Для первого запуска нужны настоящий Rust/Axum код из старой основы, проверенная миграция PostgreSQL, постоянные файлы и конфигурация.
2. На сервере один Linux-хост с Rust приложением и PostgreSQL; слушать DB на localhost/в приватной сети, не раскрывать 5432 в интернет.
3. Браузерный просмотр: выделенный HTTPS-домен/поддомен с ограниченным доступом; `robots noindex` до публикации. Нужен адрес доступного тестового сервера.
4. В CI собирать приложение на закреплённых версиях, проводить миграции и тесты. При неуспехе deploy не запускается.
5. Развёртывать в отдельную новую release-директорию/контейнер, затем проверять HTTP readiness и пользовательскую цепочку. Только после успешной проверки переключать живой маршрут. Иначе откат на прежнюю версию.
6. Секреты только в GitHub Actions Secrets/Variables и в закрытой конфигурации сервера, никогда в публичном репозитории: `DEPLOY_HOST`, `DEPLOY_USER`, `DEPLOY_SSH_KEY`, `SSH_KNOWN_HOSTS`, `DATABASE_URL`, `PUBLIC_ORIGIN`. Секреты `DATABASE_URL` держать отдельно на сервере при возможности.
7. До настройки сервера, имени хоста, проверенного SSH fingerprint, отдельного пользователя для выкладки и защищённого окружения GitHub Actions **автоматическое развёртывание не включать**.
8. При сохранении данных пользоваться совместимыми миграциями PostgreSQL; резервные копии и тест восстановления обязательны до ограниченной беты.

Инфраструктура не обязана совпадать с ранее настроенной Chaptera: чужой сервер/контейнер/порт/домен без прямого решения не переиспользовать.
