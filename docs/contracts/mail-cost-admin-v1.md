# MAIL-01h2 — system-mail budget controls in /odmen

The operator-approved 100/300/400/500 RUB thresholds are editable at /odmen/system-mail, separate from member messages. Local estimate and remaining headroom, month, reservation count, free allowance and threshold warnings are displayed; not provider billing or confirmed delivery. Whole rubles only, bounded 1..100000 RUB, ordered thresholds. No automatic increase. Free allowance depletion is a warning, not a registration cutoff.

GET and POST require a live administrator session, with repository-side recheck using shared locks on user/session/role. Browser POST requires existing Origin/CSRF checks. Compare-and-swap revision prevents two operator forms overwriting each other; stop is idempotent and independent of revision. The quota singleton lock serializes changes with reservations and pre-submission checks. Append-only PostgreSQL audit contains actor ID, previous/new values and revisions, not secrets. Lowering a limit or stopping prevents new permitted work, but cannot revoke an in-flight external submission. This interface cannot enable sending or initialize/overwrite monthly usage. No paid call, no logging service, no mail worker. Actual provider usage/recovery reconciliation, protected credential setup, bounded SMTP adapter, external warning delivery, comprehensive prevented-send/delivery metrics and production activation remain separate gates.

Existing admin_jobs_http_pg target in the shared runtime shard exercises real HTTP authorization, CSRF, stale/concurrent forms, no activation by edits, idempotent stop and immutable audit. Pure tests cover ordered numeric values and render safe aggregate status. Prior known registration Clippy type-complexity and Postbox rustfmt corrections are included on this integration branch; extraction of unchanged member message route wiring keeps auth.rs under the architecture line limit. No policy/test weakening, no deployment. CI pending.
