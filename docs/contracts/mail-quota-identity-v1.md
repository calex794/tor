# MAIL-01f2a — versioned keyed quota identifiers

The mail module uses the existing locked HMAC-SHA256 and zeroize dependencies. An independently provisioned 256-bit key is accepted as 64 hex characters; missing, malformed and all-zero values are rejected. No random/default fallback. The key has no Debug or serialization implementation and is held in a zeroizing owner. The v1 recipient, IPv4, IPv6 and key-binding namespaces are distinct. Account case normalization is preserved; callers must first use MAIL-01a delivery_address, including IDNA, and pass only the canonical transport address. No provider alias rewriting. Mapped IPv4 and alternate IPv6 spellings are canonicalized; loopback/unspecified/unknown ingress remains the restricted unknown bucket. IPv6 is limited per address, not a subnet, in this initial policy.

The quota ledger accepts opaque keys constructed by the signer. Under the existing singleton lock, bind a new empty ledger to the HMAC key-binding digest. A different key or historical unbound ledger refuses reservations (KeyMismatch) without resetting counters. The binding is not a backup of the key. Retain the same independently encrypted key across service restart, update and disaster recovery. Do not rotate it silently; changing the key requires a separately accepted transition preserving the rolling window. The DB stores no original addresses, IPs or secret in this subsystem; keyed digests are pseudonymous rather than anonymous.

MAIL-01f2b / MAIL-05 must connect existing verified_client_ip at trusted ingress to the immutable signup event, resolve the current recipient and derive the digest from canonical transport address; never accept arbitrary digests or forwarded headers from clients. Runtime key loading/storage/recovery, suppression key lifetime and this integration are not implemented by this PR. No SMTP or deploy. Unit tests verify deterministic recovery, domain separation, case/alias behavior, malformed secrets, IP canonicalization and the transport input contract. The existing disposable PostgreSQL quota test verifies key binding, mismatched key rejection and restart without losing reservations.
