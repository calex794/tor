# MAIL-01g2b — authenticated Postbox feedback relay (default OFF)

Implementation: private Yandex Cloud Function (Python stdlib, ops/postbox-relay/index.py) receives the documented Data Streams trigger {"messages":[...]} batch. Dedicated stream and IAM-restricted invocation; no publicly invokable function. Only the configured identity and one-recipient explicit 5.1.1/abuse events are forwarded. Strip unrelated headers, diagnostic text, subject, tags, tracking and all other fields. TLS verification enabled; fixed HTTPS URL, no redirects or proxies. Sign exact minimized JSON bytes with a separate 256-bit relay secret, HMAC-SHA256 over ASCII prefix "tor/postbox/relay/v1\n", canonical Unix timestamp, newline and body. Receiver verifies constant-time MAC before JSON parsing, permits at most 300 seconds clock skew and requires configured identity. Stable quota key is never shared with Cloud Functions. Duplicate headers rejected. Receiver route is absent unless explicit TOR_MAIL_POSTBOX_RELAY_ENABLED=1, secure web configuration and both distinct valid keys + identity. Bounded 64 KiB body, four concurrent DB operations and five-second database deadline. No session login, no CSRF exception on any existing route. Return 204 only for committed/duplicate/nonactionable events; uncorrelated 409 and DB failure/key mismatch/overload 503 cause retry. All other non-204 also fail the cloud invocation. Retry with fresh signature and same eventId; durable DB event fence prevents duplicated suppression. No raw JSON or secrets in logs/storage. If acknowledgement is lost after commit, replay is safe.
