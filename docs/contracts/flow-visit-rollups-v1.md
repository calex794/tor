# FLOW-02 — серверные HTML-потоки и наблюдаемые визиты

**Статус:** первый исполняемый срез сбора и хранения поверх существующего RIL, не готовый visitor-dashboard. Архитектурное решение: [Notion FLOW](https://app.notion.com/p/41132a84beec81c08561f999c74144fb), контракт [FLOW-01](flow-analytics-v1.md).

## Что измеряется

| Метрика | Определение | Ограничение |
| --- | --- | --- |
| html_requests | Успешные GET 200 HTML от известных публичных/частных страниц; исключены API, static, ops, ошибки, редиректы и очевидные боты | Это HTML-запросы, не люди и не уникальные сеансы |
| opted_in_html_requests | Подмножество HTML-запросов, снабжённых ранее подтверждённым RIL-согласием и серверным HMAC | Действующий consent-middleware покрывает лишь часть маршрутов |
| observed_opted_in_visit_starts | Первое наблюдение opted-in HMAC или событие после 30 минут неактивности на одном серверном процессе | Перезапуски, многоинстансность и вытеснение из bounded state способны завышать число |

**Анонимные визиты и уникальные посетители сайта не измеряются**. Анонимные HTML-запросы не склеиваются в историю без согласованной политики приватности и согласия. Даже при нулевых opted-in visit starts нельзя утверждать, что людей на сайте не было. Антибот-фильтр по User-Agent только грубая эвристика, отсутствие признака бота не доказывает, что запрос создан человеком.

## Агрегированные измерения

- Пять поверхностей: главная, каталог, карточка книги, читалка, ограниченные страницы личного кабинета.
- Четыре сигнала источника: внешняя поисковая система, другой внешний реферер, резерв внешней платной атрибуции, прямой или неизвестный. Метка внешней оплаты зарезервирована, но никакие оплаченные источники автоматически не подтверждаются.
- HTTP Referer — недостоверный запросный сигнал, не verified first-touch acquisition. Внутренняя навигация не записывается как внешний SEO. Не сохраняются сам Referer, URI или поисковая строка.
- Все срезы с UTC-часом и низкокардинальными цифровыми кодами, максимум 5 × 4 строки на час.
- Время корзины определяется фоновым flush через существующую RIL-помпу; пограничный запрос может попасть в следующий час.

## Данные и безопасность

Добавлены таблицы ril_flush_flow и ril_flow_hourly; оба набора содержат только UTC-корзину/батч, код поверхности, код источника и счётчики. Не содержат IP, UA, cookies, email, аккаунт, HMAC, полный путь, query, текст книги или идентификатор посетителя. Есть фоновая очередь RIL и его UUID батча, исключительная аренда, fencing epoch, транзакционная материализация и повторные попытки без двойного применения.

Для чтения доступен ограниченный запрос PgRilRollups::read_flow_hourly(hours), 1–720 часов, без идентичностей. Часовые агрегаты удаляются по 30-дневной политике RIL, завершённые батчи остаются на 90 дней как защита от повторной материализации. Финансовые факты C/D, покупки, права и персональные данные RIL не переписываются. Opt-out удаляет in-memory субъект в существующем RIL privacy barrier.

**Никакого отдельного EventStore, Kafka, ClickHouse, cookie или трекинг-пикселя.** HTTP не пишет SQL и не ждёт сборщика; при перегрузке телеметрия может теряться, не блокируя чтение.

## FLOW-02b — дополнительный охват согласованных публичных просмотров

**Новая возможность в PR FLOW-02b:** при `TOR_FLOW_PUBLIC_OPT_IN_ENABLED=1` и уже существующих `TOR_RIL_SINGLE_INSTANCE=1`, `TOR_RIL_HMAC_KEY` зарегистрированный читатель, который **явно согласился** на поведенческую телеметрию, может быть отмечен в рамках четырёх публичных HTML-маршрутов: главной, каталога, карточки книги и бесплатной читалки. Значение флага **по умолчанию выключено**. На public-маршрутах проверка live-сессии и consent выполняется только для присутствующего, корректного session-cookie, внутри A-owned middleware с максимальным ожиданием ответа БД 25 мс. Запрос читателя продолжается даже при отказе проверки, ошибке БД или тайм-ауте; учёт становится неполным, а не блокирует доступ.

Проверенный маркер HMAC передаётся исключительно через внутреннее расширение Axum-ответа. RIL по-прежнему сам принимает только известные успешные HTML-страницы и ничего не сохраняет про пользователя в агрегатах. Не создаётся новый cookie, SDK, fingerprint, постоянный session-ID или second event journal. Отмена согласия очищает HMAC-состояние через существующий RIL privacy-barrier; текущий login-cookie остаётся только в account boundary.

**Принципиальные ограничения:** флаг не делает отслеживание anonymous законным или технически разрешённым. Site-wide distinct humans, точное число визитов, first-touch SEO и возвраты по месяцам всё ещё **не реализованы**. Браузерный `SameSite=Strict` cookie может отсутствовать при первом внешнем переходе; следовательно, эта метрика — частично наблюдаемые opted-in sessions, а не все посетители. Отдельное решение по consent/данным для anonymous требуется до общего «Unique visitors» dashboard. Включать флаг на production можно только после отдельного решения и измерения задержки; PR его не включает.

## Проверки

- Unit: две страницы за один визит, новый визит через 30 минут, отмена согласия, вместимость и вытеснение, неизвестные поверхности.
- Unit: клиентская/неопознанная страница, известный бот, неправильный тип ответа и ошибочные HTTP-статусы не становятся подтверждённым просмотром.
- Axum: реальный HTML 200 проходит; API и Googlebot не учитываются как pageview.
- PostgreSQL 18: расширен существующий тест ril_06_pg_crash_replay_fencing_and_daily_rollups — сзади тот же RIL batch, старый lease не применится, повторённый batch id не удваивает счётчики, часовая read model ограничена.
- Для приёмки — exact-head cargo fmt, Rust tests, Clippy, real PG18 migrations/HTTP, Repository rules, Integration CI, затем проверка main. Деплой и применение к постоянной базе не входят в PR.

## Невыполненные части FLOW-02

1. Уточнить разрешённый охват consent для public book/catalog/reader: текущая выборка авторизованных страниц не позволяет считать opted-in sessions всех посетителей.
2. Отдельно решить юридически и продуктово, допустим ли анонимный opt-in session ID; до этого показывать только HTML-запросы, не уникальных людей.
3. Добавить доверенный acquisition-level first-touch и связать его с последующим чтением в FLOW-03. Request-level Referer не заменяет этот слой.
4. Добавить административную панель и качество телеметрии в FLOW-04/06.

**Статус задачи:** реализация серверного среза FLOW-02; полный FLOW-02 пока не принят. Код в репозитории не доказывает, что новая миграция была применена к production или что появилась статистика настоящих визитов.
