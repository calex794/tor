# PROMO-P1b-00 — безопасный тип оффера TOR / Boosty

**Дата:** 15.11.2026 · Источник [Notion «Промо»](https://app.notion.com/p/41932a84beec81e4b1b1d21745360b2b) · Ожидает PR #915 (Book-only промополоса).

## Область этого среза

В `tor-ads::domain::promo_offer` вводятся только **нефинансовые типы**: `PromoTarget::Book/Package/Boosty`, `ExternalKind::Discount/Trial/Post/Bundle`, `PromoAudience`, `PromoCreative`, `PromoDraft` и проверка HTTPS-ссылки Boosty. Все бизнес-решения до server-side rendering и PostgreSQL пока выключены. Этот срез не добавляет новую рекламную таблицу и не подменяет F/FLOW editorial.

## Проверки и границы

- HTTPS, точный hostname `boosty.to`, непустой путь и размер до 2048 байт; без userinfo, постороннего порта, fragment, управляющих символов и произвольных redirect-хостов. Не доверять похожим поддоменам.
- URL может содержать trial/offer token в query string, поскольку ссылка предназначена для перехода читателя; **Debug всегда редактирован** и полная ссылка не должна попадать в логи/аналитику.
- Ограничены заголовок (100), подзаголовок (220), CTA (40), обязательный snapshot условий (600 символов); текст остаётся текстом, HTML экранируется только доверенным SSR.
- Временной интервал RFC3339 с явной зоной, секунды без дробей, длительность до 366 дней, приоритет 0–100.
- Аудитории только канонические: все/гости/зарегистрированные/подтверждённые покупатели глав. «Подписчик Boosty» исключён до настоящего evidence.
- Никаких имитаций купленной подписки, денег на кошелёк, customer ID, self-service автора, прямого рекламного JS или автоматического создания Boosty-промокодов.

## Следующие необходимые вертикальные срезы (не реализованы этим PR)

1. Хранилище campaign/offer/creative/placement и immutable terms, CAS/аудит; единая связь с существующим `tor-ads`, без перераспределения прав из D.
2. Admin-only SSR с Origin/CSRF/replay, preview 390/1440 и явным ручным подтверждением актуальности внешнего предложения.
3. Реальная безопасная выдача с повторной проверкой eligibility, kill switch и fail-soft, анонимными `outbound_boosty` агрегатами (не покупками) и Chromium/PostgreSQL приёмкой.
4. Только после подтверждения провайдера — узкие Boosty-сегменты и финансовая интеграция по отдельному D-решению.

**Верификация этого среза:** `cargo test -p tor-ads --lib promo_offer`, `cargo fmt --all -- --check`, `cargo clippy` и полный Repository rules/Integration CI по точному SHA. Без приёмки не считать P1b завершённым.
