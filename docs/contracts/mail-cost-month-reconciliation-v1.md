# MAIL-01j — stopped-only budget reconciliation

A new month is never automatically credited with 2,000 free messages. A stopped operator must independently verify provider billing scope, current tariff, remaining exclusively available free allowance, prior/external charge and the upper bound on attempts not represented in a recovered database. When free usage is uncertain use zero allowance. If prior usage cannot be conservatively bounded, keep sending stopped. The evidence SHA-256 is only a reference to the reviewed evidence, not proof of authenticity or completeness.

The repository command requires a live administrator session, the current Moscow month, the current policy revision, the same quota lock used by reservations and a disabled policy. It may create the current month or tighten it. Existing free allowance can only decrease; baseline, upper rate and accumulated attempts can only increase. The floor must cover all known distinct reservation/correlation attempts since the start of the month, including future-dated evidence. Independently account for lost or pruned history; double counting uncertain amounts is conservative. Old months are untouched. No resetting short quotas or suppressions. The final five minutes of a billing month remain blocked.

The numeric before/after values and evidence digest are stored in an append-only receipt in the same transaction as the month and revision update. No invoice, credentials, recipient address or message body is stored. Stale or concurrent requests conflict; no automatic enable, quota increase, refund or provider API call. This is a local estimate, not the actual Postbox bill. It is not a complete restore/activation fence: a restored older database cannot detect all missing attempts on its own.

This slice is repository-only. The future administrator UI must add CSRF/Origin, explicit evidence confirmation and a separate activation gate; no HTTP route or credentials in this PR. No production changes. The test is registered in the existing serial Commerce PostgreSQL suite, which exercises permission, stopped-only/current-month/revision checks, known-attempt floor, no refunds, concurrent revisions, audit and preservation of historical months.
