# FLOW-01 — единый контракт измерения аудитории TOR (v1)

**Статус:** исполняемая семантика метрик, *не* сбор визитов и *не* работающая панель. Реализовано только в `tor-contracts::flow`, тесты `crates/contracts/tests/flow_contract.rs`. Источник: [план FLOW в Notion](https://app.notion.com/p/41132a84beec8148bc7ee347c6388e55), [карта существующих источников](https://app.notion.com/p/41132a84beec81c08561f999c74144fb) и [контракт доменных событий](events-analytics-v1.md). Следующий пакет FLOW-02 должен реализовать сбор/агрегирование визитов; FLOW-03 — сопряжение с чтением.

## 1. Разделение уровней и владельцев

| Уровень | Что измеряется | Системный источник | Что **не** выводим |
| --- | --- | --- | --- |
| HTTP telemetry | Запросы, коды, задержки, семейства маршрутов | RIL | Количество людей, источники книг |
| Site visit | Успешные человеческие HTML pageviews и сеансы, вход/последняя наблюдаемая поверхность | Будущий FLOW-02, доверенный роутер | Постоянная личность анонима, фактическое закрытие вкладки |
| Discovery touch | Выбор книги через каталог, внутренний поиск, REC или внутреннюю рекламу | F/REC/Ads, серверно подтверждённые переходы | Внешний поисковый источник |
| Reading | Открытие страницы главы, доверенное начало/завершение, сохранение | C / `reader_chapter_completions` + outbox | Фактическое время чтения из HTML GET |
| Money | Зафиксированная покупка и рекламное списание | Только D / канонический ledger | Списание по client click или impression |

FLOW-01 задаёт правила проверки, **не создаёт** новую таблицу, идентификатор или источник истины. Любые новые сквозные связи строятся поверх существующих C/F/D событий; чувствительные данные не попадают в RIL.

## 2. Две независимые оси атрибуции

**AcquisitionChannel** — источник входа на *сайт*: `ExternalOrganicSearch`, `ExternalReferral`, `ExternalPaid`, `DirectOrUnknown`. Без валидированного сигнала «direct» нельзя установить отдельно от отсутствующего referrer. Будущий FLOW-02 обязан фиксировать происхождение значения и учитывать spoofing/отключённый referrer, согласие и приватность. Данные Search Console / Яндекс Вебмастера подтверждают агрегаты поиска, но сами не являются HTTP-сеансом.

**DiscoveryChannel** — источник *выбора книги внутри сайта*: `OrganicRecommendation`, `PaidInternalAdvertisement`, `Catalogue`, `SiteSearch`, `LibraryOrFollow`, `DirectBookOrUnknown`. Внешний organic search и `SiteSearch` не смешиваются. Реклама не получает органический credit и наоборот. Внутреннюю рекомендацию нельзя выставлять на основании фальшивого клиентского клика: использовать подписанный/серверно подтверждённый receipt.

Один пользователь: Яндекс → сайт → рекомендация книги B → подтверждённое завершение главы. Визит получает `ExternalOrganicSearch`, открытие B — `OrganicRecommendation`, факт завершения главы **один**. Два измерения относятся к одному результату, а не к двум числителям конверсии.

Правило дедупликации: канонический `event_id` доменной транзакции; одинаковый `event_id` + факт + атрибуция ⇒ один результат, конфликт факта или атрибуции на том же id ⇒ ошибка/карантин (не пересчёт «в пользу» другой системы). Изменение алгоритма атрибуции требует версионирования и миграции производной read-модели, не переписывания C/D фактов. В `flow.rs` есть **ограниченный pure reconciliation helper** для контрактных тестов, а не долговременная production дедупликация.

## 3. Pageview, visit, reader и активность

- **Request** — любой HTTP ответ; RIL считает технический поток без идентичности, не DAU.
- **Pageview eligible** — только `GET`, статус `200`, действительно HTML, *известная разрешённая* поверхность `Home/Catalogue/BookDetail/ChapterReader/AuthenticatedPage`, `visibility_confirmed=true`, `TrafficHygiene::Eligible`. 404/redirect, API, asset, ops, неопознанные маршруты, подозреваемые боты и не классифицированный поток не засчитываются в **подтверждённую** воронку. Они могут оставаться в техническом RIL.
- **Hygiene Eligible** означает лишь отсутствие сработавших критериев автоматизации, **не** удостоверяет человеческую личность. Не использовать для блокировки аккаунтов/доступа/денег.
- **Visit start** — первый пригодный pageview в допустимом наблюдаемом сеансе. Повторные загрузки внутри сеанса не создают новый visit. `VISIT_IDLE_TIMEOUT_SECONDS=1800` — предложение технического интервала, а не измерение закрытия браузера.
- **Anonymous sessions** — количество наблюдаемых сеансов, а не `unique humans`. Если идентификация без согласия/допустимого основания запрещена, отчёт должен честно отражать степень измеримости.
- **Registered readers unique за 7/30/90 дней** — `DISTINCT` за **весь период** по проверенной серверной identity; сумма daily uniques может быть завышенной. Нельзя выводить уникального читателя из IP, User-Agent, пикселя или случайного токена без согласованной политики.
- **Book opened** — разрешённая карточка/навигация, **chapter opened** — успешная выдача страницы главы, **chapter started** — только подтверждённый C-прогресс, **chapter finished** — только канонический C fact/commit. Доступ к S3, HTML GET, просмотр рекламной карточки и оплата не означают дочитывания.
- **Reader returned** — повторный допущенный визит идентифицируемого читателя в определённой когорте. `D1/D7/D30` нельзя корректно считать из сумм дневных unique. Отдельный дизайн и политика хранения в FLOW-02/03.
- **Exit** — последняя наблюдаемая поверхность перед 30-минутным тайм-аутом, **не** достоверное событие ухода. Одностраничное длительное чтение не автоматически bounce; потребуется отдельное поведенческое определение без скрытого профилирования.
- **Многожанровость:** показатели по жанрам не складывать как «уникальных людей на сайте». Книга может быть в нескольких жанрах; важен знаменатель (число публичных книг, реально показанные карточки, подтверждённые чтения).

## 4. Контрактные ограничения доверия и безопасности

В `FactAuthority` разрешены только соответствующие authoritative owners:

| Факт | Владелец |
| --- | --- |
| `BookOpened` | `AuthorizedBookNavigation` после B/F видимости и успешного book handler |
| `ChapterStarted`, `ChapterFinished` | `ReaderTransaction` с подтверждением C |
| `LibrarySaved` | `LibraryTransaction` |
| `PurchaseCommitted` | `CommerceTransaction` |
| `AdImpressionBilled` | `AdLedgerTransaction` |

`ClientClaim` и `TechnicalTelemetry` не могут создавать эти результаты, независимо от внешне переданного `event_id`. Граница типизации **не удостоверяет сама по себе** реально совершённую транзакцию: это проверяет вызывающая доменная служба.

Секреты, IP, email, сырые URL/search query, читательский текст, токены сеансов/покупок, signed S3 URL не допускаются в агрегатах. Для поведенческой персонализации и идентичности соблюдать существующий выбор согласия, удаление и законодательные требования. Сроки удержания согласно [events-analytics-v1](events-analytics-v1.md) — ориентиры технической политики, не самостоятельное юридическое разрешение на хранение.

**Запрещено без отдельной работы:** переписывать RIL, запускать ClickHouse/Kafka, делать второй ledger, создавать глобальную постоянную историю посещений, включать частное отслеживание анонимов, применять production-миграции или подменять алгоритмы рекомендаций/оплаты.

## 5. Тестовые критерии FLOW-01

- `flow_01_only_successful_verified_html_pages_enter_funnel`: HTML 200 + разрешённая видимость — eligible; 404/302/500, API, static, ops, неизвестное, подозреваемая автоматизация — нет.
- `flow_01_separate_external_acquisition_from_internal_discovery`: два независимых измерения, внутренний search не внешний.
- `flow_01_search_to_recommendation_to_read_is_one_conversion_even_after_replay`: один канонический результат несмотря на повторную доставку; конфликт атрибуции fail closed.
- `flow_01_ten_chapter_events_from_one_reader_are_not_ten_unique_readers`: версия агрегации явно требует period DISTINCT для зарегистрированных читателей. Фактический DISTINCT/когорты тестируются отдельно при FLOW-02/03 (пока данных нет).
- `flow_01_untrusted_client_or_http_request_cannot_claim_domain_result`: клиентский запрос или RIL не имеют права создавать подтверждённое чтение/покупку/оплачиваемый показ.
- `flow_01_reconciliation_is_bounded_and_conflicting_evidence_fails`: ограничение размера и запрет конфликтующих фактов.

Для принятия FLOW-01 требуется **прохождение `cargo test -p tor-contracts --test flow_contract` на точном SHA + стандартный CI/Repository rules и приёмка интеграционного владельца**. Наличие файла в GitHub или открытого PR не подтверждает успешной приёмки.

## 6. Следующая реализация

**FLOW-02:** выбрать правовую/техническую модель краткоживущего сеанса, один actor-independent pageview source, не блокирующий путь записи и потерянные события, часовые UTC bucket rollups; затем тесты HTTP/PG/бот/TTL/consent. **FLOW-03:** на read-only агрегатах связывать подтверждённые C события с каналами, сохранять идентичность факта, обеспечивать отсутствие двойной атрибуции и отсутствие утечки private/paid titles.
