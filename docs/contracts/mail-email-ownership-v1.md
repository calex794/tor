# MAIL 5a — account-owned mailbox proof and support source

The canonical transport and single dispatcher remain in #1367, with managed lifecycle and operator activation in its dependent branches. This slice is independent of the transport. It preserves the useful source-ownership work from #1368 without merging the alternative dispatcher, scheduling migration or local runtime.

A mailbox candidate is read only from the active account, canonicalized for transport, and bound to the exact normalized account address. Neither a DNS route, a saved address, registration evidence nor S018 news consent constitutes mailbox ownership. New or existing accounts are not implicitly verified. Verification is separate from authentication and does not change signup, login, sessions or password recovery.

The account-owned proof table holds one challenge or verified record per user; no raw proof or duplicated mailbox. A random 256-bit challenge is generated using the existing security service; only its digest enters the repository. The provisional challenge lifetime is 30 minutes and issuance cooldown is 60 seconds. Consumption requires the live authenticated actor, the current address, matching digest and database-clock expiry, under the account lock. The successful update atomically removes the challenge. Changing the mailbox or account state deletes the ownership record, including away-and-back changes. No backfill of verified flags.

The issuance primitive is not a production send permit. Before runtime wiring, move issuance into the common reserved registration-confirmation correlation transaction, bind exact committed signup evidence and quota keys, and recheck the account and proof before SMTP. Confirmation HTTP must use the existing Origin/CSRF, rate-limit and authenticated session conventions; no token in query, logs or plaintext queue. Do not connect any alternative transport or enable automatic startup in this PR. No new dependency.

Support resolves only a committed administrator reply with matching audit and current registered owner. It returns a boolean, never the private message. The future producer must enqueue only a newly committed reply to a registered owner (no historical guest backfill), and the common worker must require the verified current address, repeat ownership and final eligibility checks, and render a fixed generic notification linking to the configured HTTPS /support. Site support itself is unchanged. Project news retains a separate explicit opt-in and unsubscribe gate.

Acceptance: the existing accounts referral signup PG target and support slices_pg target cover exact ownership, single-use concurrency, wrong user/proof, expiry, cooldown, changed address, account-state invalidation, guest and foreign reply denial. Full required CI, canonical worker integration, activation/test-send and real provider acceptance remain separate gates. No deployment or real mail.

## Initial signup source and handoff

The only initial confirmation event uses the committed registration account ID as both event ID and recipient ID. New resend events are deliberately not accepted. The account source returns the canonical mailbox and captured signup evidence from one database snapshot, only for active and not-yet-verified accounts within the first 24 hours. This is a conservative initial-send window; the existing seven-day cleanup and separate 30-minute challenge expiry are unchanged. The caller must still check the existing keyed recipient/IP evidence and final reservation/correlation authority.

A bounded pending/acknowledge port uses at most 100 references ordered by capture time. Acknowledge only after the existing idempotent queue commits a receipt (including an existing identical receipt). Lost acknowledgement may repeat the reference, not create another message. Nothing invokes this port at runtime yet. An account address or state change invalidates both prior proof and signup evidence, and increments a dedicated mailbox revision. A stale in-memory candidate cannot issue a proof even if the old address or state later returns. This modifies only the new, unmerged draft migration; existing migration checksums are untouched.

This slice does not implement resend, token generation or the final atomic dispatch proof transaction. The canonical worker must install the purpose only after those admission checks and source handoff have passed acceptance.

## Charged registration proof port

Standalone account proof issuance is removed. The account-owned SQL function requires the initial event, active account and non-reused mailbox revision, acknowledged live signup source, exact leased outbox generation, charged recipient/IP/key binding, exact correlation marker and current month with no suppression. It records the outbox/generation and digest only. Initial signup issues at most one proof; even an expired initial proof is not reissued without a separately designed resend event. The previous provisional 60-second issuance cooldown is therefore superseded for the initial event. The 30-minute proof lifetime is unchanged.

The canonical mail repository must call this port in the existing correlation transaction, after validating the exact DispatchGrant and cost gate, and roll back correlation on false. The existing final send-start witness must also bind this exact proof and revision. This independent slice does not yet invoke the port from a production worker, and the SQL port is not a replacement for the canonical live activation fence. PostgreSQL tests exercise uncharged/missing marker rejection, stale revision/generation, zero digest, duplicate issuance, rollback of both proof and marker, and committed attempt binding. Account-only proof-consumption tests use explicitly test-only seeded rows.
