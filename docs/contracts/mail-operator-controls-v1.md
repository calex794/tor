# MAIL 3/6 — operator controls

This integrated gate starts with the existing /odmen/system-mail page. The reconciliation action requires live administrator session, Origin/CSRF, explicit independent-review confirmation, a current Moscow billing month and a policy revision. Unknown allowance defaults to zero. The server validates numeric fields and a nonzero SHA-256 evidence reference; the repository atomically checks the stopped policy, reservation/correlation lower bound and immutable audit. The evidence digest is only a reference; the application does not claim to verify the external billing evidence.

Pending in this same gate: fixed Postbox identity and sender configuration, independently keyed authenticated encryption of credentials, exact-intent administrator step-up, redacted read-only probe, separately quota-reserved test-send, and an independent restore/launch fence. No credentials in forms returned to browsers, audit or logs. No HTTP action or saved profile alone can enable sending. The future worker must start stopped after a restore or restart and must obtain current explicit operator approval with externally verified usage. No production SMTP, deployment or provider activation.

CI must run the existing admin_jobs_http_pg suite and RIL route/governance checks. This is a draft stacked on gate 1 until its reconciliation API is accepted; transport integration will be added to the same PR after gate 2.

## Encrypted candidate custody

The offline candidate repository uses AES-256-GCM, fresh random 96-bit nonces, and an independent 32-byte versioned key supplied by the future operator configuration. AAD binds the identity, sender, profile revision and key version. Save consumes a fresh exact-intent account step-up proof bound to the sealed bytes and old revision, under live role/session and the existing stopped budget lock. The receipt contains only numeric actor, revisions and key version; there is no active flag. Secret and access ID cannot appear in the overview. Candidate read for a future probe requires live role, stopped policy and exact revision; after I/O a future verification write must recheck the revision. No network or new key is configured by this change. Preserve the actual key and version in separately sealed recovery custody; a wrong/missing key must fail closed, and an older database cannot infer missing history. Real probe, rotation interface, verification receipt, separate activation and independent restore/launch fence remain pending.

## Browser save and non-sending probe

The system-mail page renders only identity/sender metadata and empty password fields. Saving needs Origin/CSRF, HTTPS (loopback HTTP for disposable tests only), live administrator authority, rate-limited fresh password proof bound to the exact sealed bytes and old revision, and stopped policy. The operator supplies separate TOR_POSTBOX_PROFILE_MASTER_KEY (32 bytes, standard base64) and TOR_POSTBOX_PROFILE_KEY_VERSION (positive integer) through protected server configuration; there is no default. These must be independently backed up, not stored in Git or the PostgreSQL dump. No production config is installed.

The separate probe route accepts only CSRF/revision, rate-limits each administrator, loads the exact stopped candidate, opens it with the matching key, and authenticates against the fixed SMTPS endpoint with NOOP only. No DB transaction spans I/O. Live role, stop and exact sealed bytes are rechecked before a successful response. The result is informational, not durable permission or proof of sender identity/deliverability; no activation state is created. CI must never probe the external provider. Actual probe, test-send and activation remain explicit operator actions.

## Independent process-local launch gate

LaunchFence is a separate, nonpersistent authority, initially stopped for every process. PostgreSQL's enabled bit and recovered audit rows are never sufficient. PgMailLaunch reads the current month, latest exact reconciliation values, sealed profile digest, policy revision, budget bounds and actual PostgreSQL postmaster start timestamp/database OID under the common quota lock. Missing/inconsistent observations fail closed. Review is a one-use five-minute process-local challenge bound to a live administrator session, stopped snapshot and explicit test-recipient or dispatch scope. The future handler must recheck fresh exact-intent password proof, a successful probe of that exact profile, and independently reviewed billing/restore evidence. A SHA-256 reference is not proof of authenticity.

The separate PgMailLaunch::admin_activate transaction compares the reviewed snapshot under the common guard, consumes a fresh session-bound one-use password proof with its own scope, writes an immutable activation receipt and advances the policy revision once. The process fence stays unarmed until a fresh observation confirms that exact receipt. A local stop during the transaction prevents an old result from rearming the process. A send requires both the enabled current database observation and this live process authority, exact claim/suppression/quota/feedback reservation and new monotonic counter. A test grant permits one attempt only, never dispatch. Observed PostgreSQL restart/DB switch, profile replacement, reconciliation/limit changes, month boundary, counter rollback or stop revokes the approval. Workers must share one instance and serialize the final check/send start; any observation error or reconnect must explicitly stop it. Restore procedures must stop all sending processes before logical in-place restore; an in-place rollback within the same running PostgreSQL instance and without a process restart/observed change cannot be detected from database contents alone. Independent external billing reconciliation remains mandatory after recovery. The activation transaction is internal; no HTTP enable route, test message, actual provider request or startup worker is added by this slice. The existing quota/reservation adapters must be bound to the exact activation mode and claim in gate 4 before exposing an activation action. The one-use test scope is not yet a real test-send path.
