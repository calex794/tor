# MAIL 2/6 — fixed-endpoint Postbox SMTPS

Postbox provider documentation (checked 2026-11-28): https://yandex.cloud/en/docs/postbox/operations/send-email and https://yandex.cloud/en/docs/postbox/api-ref/smtp-errors. Use the service account API-key ID as SMTP username and its secret as password, with the yc.postbox.send scope and the postbox.sender role. Use SMTPS at postbox.cloud.yandex.net:465 only. No STARTTLS downgrade, configurable host, alternative port, certificate override or plaintext path. TLS 1.2/1.3, normal hostname and public-root validation.

Lettre provides the SMTP protocol and MIME construction; Rustls supplies TLS. Disable default features, pooling and tracing. One authenticated connection permits one submission. Bound connection + authentication by 10 seconds, one submission by 20 seconds, NOOP by 5 seconds. Do not retry internally. A future dispatch worker must hold no PostgreSQL transaction over SMTP and recheck source, lease, suppression, active provider, budget and external restore fence after authentication, immediately before submit. It must not reuse or persist authenticated sessions. Probe authenticates and uses NOOP only; no message is sent. A separate quota-reserved test-send is a future operator action.

Accept one bare ASCII recipient and a bounded plain UTF-8 MIME message. Validate the existing durable Message-ID marker; encode the body using base64, subject via Lettre; no untrusted raw MIME/header or BCC. The envelope sender is the selected verified identity's address, configured separately in gate 3. No attachments. Credentials, MIME, recipient and raw provider replies are not logged or returned through Debug/Serialize. Caller-owned credential strings and formatted bytes are zeroized; Lettre necessarily makes transient copies during AUTH and message encoding, so this is not a guarantee of complete memory erasure.

Final DATA 250 is accepted, even if the connection immediately closes or the message identifier is absent. Only the exact documented queued response yields a validated provider message ID; the existing durable marker is still available for event correlation. A definitive 4xx/5xx means nonacceptance of that one SMTP transaction, not a confirmed recipient bounce; permanent provider rejection needs operator/policy handling, not blind replay. A lost, malformed or timed-out final response is uncertain and must not automatically retry. AUTH/connect failures occur before submission and are separate. No live provider calls, deployment, actual SMTP credentials or background activity in this gate.

Offline loopback tests use a throwaway private CA and localhost test key, never trusted by production. They cover verified TLS, name mismatch, authentication rejection, redacted single-recipient MIME, accepted/lost acknowledgements, explicit negative replies, bounded timeout, and NOOP without submission. Full CI, committed Cargo.lock and dependency security checks must pass before merge.
