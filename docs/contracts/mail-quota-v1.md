# MAIL-01f1 — persistent outbound quota reservation

The initial shared provider budget (not a claim about the operator's approved quota) is 200 attempts per rolling 24h and one reservation per second. News is admitted only while total rolling usage is below 150; the remaining 50 are reserved from news for registration/support. Registration confirmation: at most three attempts per canonical mailbox per rolling 24h, at least 120 seconds apart, at most ten per trusted signup IP per rolling 24h. Unknown IPs share a restricted bucket; they do not bypass the limit. All limits are conservative defaults and may later be lowered or changed only within an approved provider quota.

The PostgreSQL singleton row serializes reservations across processes, with a single database clock sample and lease/identity fence. No lock is held during DNS or SMTP. A unique (outbox ID, generation) reservation permits a single submission; a duplicate, expired claim or database error does not. No automatic refund for rejected, failed, ambiguous or cancelled submissions. Ledger rows survive account deletion and are kept for at least 48h, pruned on new reservations. All tests use a disposable local database and no SMTP.

Only opaque 32-byte recipient and trusted-IP digests are stored, never raw email/IP. MAIL-01f2 must implement the stable versioned HMAC derivation, canonical transport-domain and mailbox normalization, trusted ingress IP capture and immutable association with the registration event. All producers and admin test-send must pass one common gate before provider submission; no alternate sender. MAIL-04 must serialize SMTP submission starts (reservation rate alone does not guarantee actual send-start pacing), impose bounded timeouts, defer safe unsubmitted claims and keep the worker independent of HTTP. A committed reservation is not an SMTP receipt or proof of delivery. Admin configuration, provider-approved limit changes, retry/defer, HMAC key recovery and actual HTTP/worker wiring are pending. No real sends or deployment in this PR.

Acceptance: existing shared PG runtime Commerce shard runs all tests whose name begins mail_01_, including the new atomic quota test.
