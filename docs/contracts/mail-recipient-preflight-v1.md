# MAIL-01i — outbound recipient preflight

Compose the existing account syntax validator, bundled disposable-domain policy and shared bounded DNS cache at one service boundary. The future outbound worker must recheck the trusted account/source event, call this preflight immediately before the independent suppression and quota/budget reservations, and send only to its returned transport address. No account identity, local part or typo is rewritten. No SMTP, quota reservation, database mutation, remote validation API or registration/login behavior is introduced by this slice.

Ready means a valid SMTP subset and explicit or implicit mail route, not verified mailbox ownership or permission to send. A definitive negative route rejects only the current attempt; it never creates a durable bounce/complaint entry or deletes an account. Resolver failures and malformed/contradictory answers defer without a reservation. Invalid bundled policy data also defers. The future worker must implement bounded deferred scheduling and lease fencing; a negative domain can change and a temporary DNS error must not be terminal. Do not retain PreparedRecipient beyond the current attempt or log its address. No full mailbox is sent to DNS.

The caller supplies the reviewed disposable mode, initially Observe. Listed domains are only a signal in Observe; Enforce is not activated by this slice and requires an explicit reviewed decision. Typo hints remain advisory, independent of delivery decisions. One shared preflight instance owns one bounded cache per runtime, reused across workers. The tests use fake DNS, verify early rejection without network calls, default Observe and unchanged typos, IDNA cache coalescing across mailbox local parts, definitive negatives, implicit MX and temporary failures.

Integration gate: cargo test -p tor-accounts services::recipient_preflight and full required CI. Actual dispatch integration, durable retry scheduling, metrics, budget reconciliation, credentials, SMTP and operator activation remain pending. No deploy or provider calls.
