# MAIL-01b2 — live DNS transport (Draft)

Adapter: Hickory Resolver 0.26.4 (pinned; official tag https://github.com/hickory-dns/hickory-dns/tree/v0.26.4). Use system-config and tokio; no recursive resolver, arbitrary external provider or SMTP probing. Query absolute DNS names, ignore hosts file, preserve response status and remaining TTL; classify NXDOMAIN/NODATA as definitive only when SOA and negative TTL are present. Treat all other errors as Retry. The existing MAIL-01b1 service supplies an outer 2-second per-lookup budget; resolver timeout 1.5 seconds, one attempt, one server per concurrent request; Hickory internal cache disabled, with intermediate CNAME records retained and TTL caps 24 h / 1 h; the bounded application cache owns the domain decision. Application-level concurrency/coalescing/cache are MAIL-01c. The adapter is not wired into registration or real sending yet.

Deterministic UDP loopback fixture covers MX, CNAME, Null MX, A/AAAA fallback, SOA-backed NXDOMAIN/NODATA, unsupported negative response without SOA, SERVFAIL, REFUSED and timeout. No public DNS, mail addresses, API keys or real messages in CI.

Dependency lock: generated by Cargo in CI run 45887423526, then reconstructed from its exact unified diff and checked against the generated Git blob hash. The temporary workflow step is removed. No deployment or merge before RustSec and full integration acceptance.

CI run 45891780564 exposed a CNAME TTL regression with an already-queried MX target. Hickory 0.26.4 can reuse the target cache without preserving the shorter alias lifetime. Disable the internal cache, retain intermediate records, clamp positive lifetime to the minimum answer TTL and treat a negative response for a different CNAME target as inconclusive. The original CNAME TTL assertion remains intact; the repeated wire test must pass before acceptance.
