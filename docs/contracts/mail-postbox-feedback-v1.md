# MAIL-01g2a — Postbox durable correlation and feedback parsing

Provider reference (checked 2026-11-27): https://yandex.cloud/ru/docs/postbox/concepts/notification ; https://yandex.cloud/en/docs/postbox/api-ref/smtp-errors ; https://yandex.cloud/ru/docs/postbox/operations/create-configuration. Postbox sends JSON through Data Streams with at-least-once delivery and eventId. It assigns mail.messageId; successful SMTP receipts contain the provider ID. Current documented commonHeaders.originalMessageId exposes the Original-Message-ID supplied by the sender.

For every single-recipient submission, first reserve quota, then commit an independent correlation row using an unpredictable 256-bit marker. Supply the returned value as Original-Message-ID (project domain pandaolate.ru); never allow clients to choose it. A repeated prepare or invalid/stale/unreserved claim cannot authorize sending. Bind the provider message ID from the successful SMTP response; a verified event containing the exact precommitted marker can recover that binding after an ambiguous receipt. Require identity, message/marker and HMAC recipient to match; never guess the address from a header. One provider ID per identity/attempt. Correlation and bounded event ID replay fences survive queue/account deletion, quota pruning and restart for up to 90 days. No original address, IP, diagnostic text, subject, message body or token is written. Key mismatch fails closed. Duplicate events cannot refresh the suppression. Suppression writes and event deduplication are one transaction using the quota guard.

Only explicit Permanent/Undetermined Bounce with exact enhanced recipient status 5.1.1 and compatible action, or a single matching abuse Complaint, can create suppression. All other event types/statuses including Suppressed, 5.7.1, ambiguous recipients and missing evidence are ignored or rejected; never parse free-form diagnostics into a block. One recipient per submission is mandatory. Payload max 64 KiB. No engagement tracking. Hard-bounce expiry remains 30 days from the attempt. Complaints do not expire automatically.

This is NOT authentication and does NOT create a public HTTP callback. MAIL-01g2b must consume the dedicated Data Streams subscription through authenticated cloud access or a separately authenticated relay; validate the stream/identity, handle checkpoints, replay, bounded input, backpressure and dead letters without storing raw PII. SMTP MAIL-02/04 must set the header before submission and bind the exact receipt ID. Real cloud acceptance must prove that Postbox preserves the original marker, receipt correlation, correct event classification and provider retries; do not enable actual sending or ingestion until then. Ninety-day correlation is provisional; provider billing/retention and consent requirements must be checked before provisioning. No real network calls or deployment in this PR. Deterministic parser tests and PG test in the existing Commerce shard cover mismatch, duplicates, late feedback, unknown receipt, restart and cleanup.
