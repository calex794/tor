# ADM-01 — административный аудит; первый исполняемый потребитель E-11

Источник требований: [административный план](../roadmap/admin-execution-contract.md).
Общие поля `admin_action_audit` добавлены миграцией
`202610310100_support_chat.sql`; пока пишет только поддержка. Это не реализация
остальных ADM-01…12 и не открытие остальных административных маршрутов.

Авторитет роли — `PgAccounts::session_actor`: действующая сессия, active account
и актуальная глобальная роль. HTTP не принимает административный user_id из формы.
Гость — 401, действующий пользователь без роли — 403, недоступная БД — 503.
Все новые административные запросы имеют no-store, запрет встраивания и CSP.
Статический контроль разрешает только пять точно перечисленных операций
`support_admin`, а остальные /admin и /internal остаются запрещёнными.

GET страницы/списка/poll не изменяют состояние. POST ответа и отметки требует
Origin/CSRF; действие, resource ID, проверенный actor и сгенерированный сервером
request_id записываются вместе с эффектом в одном PG commit. Request ID этого
локального командного аудита пока не объединён с диагностическим request trace.
Содержимое сообщения, сырой/хешированный гостевой ключ, IP и client ID в журнал
не копируются. История append-only, удаление аккаунта её не стирает.

Для `support.reply` resource — канонический support_message; уникальный partial
index не даёт повтору создать второй успешный audit. Для `support.read` journal
добавляется только при продвижении read cursor, чужой conversation/message
получает 404 и не меняет cursor. before_revision/after_revision остаются NULL,
поскольку message ID не является редакцией административного объекта.

Все остальные административные команды требуют собственных контрактов/тестов.
