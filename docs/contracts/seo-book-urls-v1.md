# SEO-03 — постоянный адрес книги, основа SEO-04

Статус: реализация в отдельной ветке; слияние и выпуск только после CI.
Источник: [SEO-BASE-01](https://app.notion.com/p/40632a84beec81bc9fa7eba5030367f6), сценарий S060/F-08/H-10.
Эталон: [SEO NEwBOO](https://github.com/HeisLuka/newboo/blob/main/backend/app/services/seo/metadata.py) и [страница книги NEwBOO](https://github.com/HeisLuka/newboo/blob/main/backend/app/web/routes/books_detail.py).

## Принятое решение

- Один постоянный URL книги: GET /books/{id}, где id — ненулевое десятичное число без ведущих нулей. Стабильный числовой идентификатор важнее изменяемого названия. Внешний вид, HTML-шаблон и ссылки на чтение не меняются.
- Существующие публичные ссылки вида /books/42 сохраняются без редиректа и без изменения базы. Переименование, перевод названия на кириллицу или китайский язык не создают новый URL. Отдельные slug/alias-маршруты не вводятся.
- Варианты /books/042, /books/0, /books/%34%32 и прочие альтернативные написания не отдают вторую карточку книги. Неподтверждённый идентификатор не перенаправляется на потенциально закрытую страницу; доступ решает прежний B/C read-path.
- Параметры страницы оглавления остаются рабочими (limit/after). Они не входят в постоянный адрес; правила SEO-01 уже исключают страницы продолжения из sitemap и индекса.
- Наличие URL не даёт права индексации: при Disabled и для скрытых/платных материалов действует прежний запрет. SEO-03 не добавляет robots, sitemap, новую выдачу платного текста, Nginx, DNS и не меняет VPS.

## Техническая граница

- В tor-search/domain/seo_urls.rs единый тип BookUrl для адреса и строгой проверки написания; его используют SEO-01, публичные карточки и маршрут книги.
- Для SEO-04 добавлен TrustedSeoOrigin, принимающий только явно настроенный HTTPS DNS origin без пользовательских заголовков, пути и учётных данных. Пока он не подключён к HTML — никаких канонических тегов или изменения индексации этим PR нет.
- При следующем SEO-04 подключить rel=canonical, robots, Open Graph и JSON-LD к уже проверенному SeoDecision и TrustedSeoOrigin. Не брать host из HTTP. На карточке книги выводить метаданные из той же опубликованной проекции B/C, что и HTML.
- Если при миграции обнаружатся прежние адреса NEwBOO, которые не соответствуют /books/{id}, сначала собрать доказанную таблицу алиасов, проверить разрешённость книги, затем отдельно добавить точечные 301. Не угадывать старый идентификатор по заголовку и не перенаправлять черновики.

## Проверки

- Rust тесты BookUrl, включая 0/ведущие нули/Unicode/экранирование/переполнение и стабильность идентичности при переименовании.
- HTTP браузерных и модульных проверок: /books/1 остаётся 200, /books/01 не отдаёт вторую страницу, /books/3 закрыт, допустимая пагинация продолжает работать.
- HTTPS origin принимает только доверенную конфигурацию; невозможно собрать адрес через Host/X-Forwarded-Host.
- GitHub Actions: Repository rules, форматирование, Rust, PostgreSQL, визуальные проверки. Если красные — не объединять.

## Вне этого PR

Полная SEO-04 вёрстка метаданных, sitemap, механика поколений, переключение режима индексации, второй Shadow-web, реальные 301 со старых алиасов без карты соответствий и обновление работающего VPS.
