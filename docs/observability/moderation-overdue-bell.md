# MOD-OPS-ALERT-01 — внутренняя проекция в колокольчик (пока не включена)

Этот этап #661 использует **уже существующие** `outbox_events`,
`event_deliveries` и `user_notifications`. Нового внешнего канала,
email, push или публичного API нет.

`PgNotifications::project_moderation_overdue_to_admin_bell(limit)` — метод
транзакционной проекции. По умолчанию он **не запускается автоматически**.
Предлагаемый получатель — действующий администратор сайта (не модератор
команды книги). Размер вызова — от 1 до 100 новых записей.

## Строго выключенная по умолчанию периодическая проекция

Код планировщика существует, но процесс не запускает его без **трёх
независимых явных настроек**:

```text
TOR_MOD_OVERDUE_OBSERVER_ENABLED=1
TOR_MOD_OVERDUE_BELL_DELIVERY_ENABLED=1
TOR_MOD_OVERDUE_BELL_RECIPIENT_POLICY=all-active-site-administrators
TOR_MOD_OVERDUE_BELL_SLA_POLICY=elapsed-hours-24-72
```

Первая строка включает сбор наблюдений, остальные три — доставку в
колокольчик и осознанный выбор адресатов и порогов. Отсутствие флагов
означает полное отсутствие фоновой доставки; неполный набор, другое
значение, demo, отсутствие PostgreSQL или TOR_AUTH_ENABLED=1 завершают
запуск ошибкой, а не включают рассылку. Перед стартом выполняется проверка
наличия схемы без миграции; фоновая задача стартует только после
успешного связывания HTTP listener. Первое выполнение откладывается
на 15 секунд для начальной сверки сигналов, затем не чаще раза в 60
секунд обрабатывается до 100 новых пар «сигнал — получатель». Транзакция
и уникальный ключ обеспечивают безопасное повторение после сбоя.
Работает только внутренний колокольчик, без email/SMS/push.

Выбор адресатов `all-active-site-administrators` и календаря
`elapsed-hours-24-72` остаётся **предложенным, не утверждённым
бизнес-правилом**. Эти настройки не должны применяться в production
без отдельной приёмки политики, прав доступа и эксплуатационных условий.

Для каждой пары (сигнал просрочки, администратор) в одной транзакции
появляются событие и уведомление в существующем колокольчике, вместе с
подтверждением доставки. Уникальный ключ события
`mod-overdue-bell:<signal-id>:<recipient-id>` предотвращает дубликаты при
повторе, сбое транзакции и двух одновременных вызовах. PostgreSQL advisory
lock сериализует экземпляры этого внутреннего проектора.

Перед проекцией повторно проверяются активный аккаунт и роль
администратора, предпочтение на уведомления, текущий статус и ревизия
заявки, наличие решения и запрет рассматривать собственную заявку на
удаление. Текст уведомления не содержит имя автора, название книги,
имя модератора, причину отказа или приватный путь S3. Ссылка ведёт
только на закрытую страницу `/moderation/books/alerts`.

При **каждом чтении колокольчика**, отметке прочтения и массовой отметке
SQL дополнительно проверяет, что получатель по-прежнему активный
администратор, а заявка всё ещё актуальна. Отзыв роли или завершение
рассмотрения скрывают даже уже материализованное уведомление без
ожидания следующего фонового сканирования.

**Не реализованы/не утверждены:** эксплуатационное включение
автоматической доставки, SLA и назначение ответственного/дежурного,
повторная регистрация с собственным timestamp, внешняя доставка и
уведомления по почте/SMS/push. Новые изменения в production, на VPS и
постоянных БД не выполнялись.
