# MOD-OPS-ALERT-01 — внутренняя проекция в колокольчик (пока не включена)

Этот этап #661 использует **уже существующие** `outbox_events`,
`event_deliveries` и `user_notifications`. Нового внешнего канала, email,
push, публичного API или фонового доставщика здесь нет.

`PgNotifications::project_moderation_overdue_to_admin_bell(limit)` — ручной
внутренний метод, который **нигде автоматически не вызывается**. Политика
получателей ещё не утверждена. Предлагаемый, пока выключенный вариант
предназначен только действующим администраторам сайта, не всем модераторам
команд книг. Размер одного вызова — от 1 до 100 новых записей.

Для каждой пары (сигнал просрочки, администратор) в одной транзакции
появляются событие и уведомление в существующем колокольчике, вместе с
подтверждением доставки. Уникальный ключ события
`mod-overdue-bell:<signal-id>:<recipient-id>` предотвращает дубликаты при
повторе, сбое транзакции и двух одновременных вызовах. PostgreSQL advisory
lock сериализует экземпляры этого внутреннего проектора.

Перед проекцией повторно проверяются активный аккаунт и роль
администратора, предпочтение на уведомления, текущий статус и ревизия
заявки, наличие решения и запрет рассматривать собственную заявку на
удаление. Текст уведомления не содержит имя автора, название книги,
имя модератора, причину отказа или приватный путь S3. Ссылка ведёт
только на закрытую страницу `/moderation/books/alerts`.

При **каждом чтении колокольчика**, отметке прочтения и массовой отметке
SQL дополнительно проверяет, что получатель по-прежнему активный
администратор, а заявка всё ещё актуальна. Отзыв роли или завершение
рассмотрения скрывают даже уже материализованное уведомление без
ожидания следующего фонового сканирования.

**Не реализованы и не включены:** автоматическое расписание проекции,
утверждённый SLA, назначение дежурного/получателя, повторные заявки на
регистрацию с собственным timestamp, внешняя доставка, уведомление по
почте/SMS/push. Подключение метода к периодическому воркеру требует
отдельного решения по бизнес-политике и приёмки. Новые изменения на
production/VPS и постоянных БД не выполнялись.
