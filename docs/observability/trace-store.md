# OBS-03 — независимое хранение технических трасс TOR

**Состояние:** отдельная служба Rust + SQLite, выключена по умолчанию. Она не заменяет RIL, PostgreSQL и систему безопасности. Для первых проверок запускается на выделенной испытательной машине. Старые настройки и данные NEwBOO автоматически не копируются.

## Пользовательский сценарий оператора

1. В приложении появляется ошибка или медленный запрос. HTTP-ответ содержит созданный сервером \`x-request-id\`. Лог RIL/метрики позволяют узнать семейство маршрута.
2. Закончившийся HTTP-запрос вместе с ограниченными числовыми SQLx-операциями целиком попадает в выборку или пропускается целиком. При включённом отдельном процессе запись выполняется через очередь, **не задерживая ответ клиенту**.
3. Оператор смотрит архив командой \`tor-trace-store report /var/lib/tor-traces/traces.sqlite3 50\`. Команда сообщает **сколько всего записей сохранено, сколько совпало и сколько реально показано**. Это не поиск по «последним ста» под видом полного архива.
4. Служба удаляет записи старше трёх дней, хранит не более 50 000 корневых трасс и ограничивает SQLite основным файлом до 64 МиБ. Заполнение диска или отсутствие процесса не должно останавливать чтение и покупку книг.

## Изоляция и данные

- Соединение **только через закрытый Unix-сокет** с правом \`0600\` и каталогами \`0700\`. Нет TCP, публичного API, пути поиска по чужим аккаунтам или личных идентификаторов.
- Протокол \`OBS1\` — только заранее заданные числа: \`trace_id\`, одна из пяти групп маршрута, одна из пяти групп статуса, длительность, наличие SQLx, счётчик, время и максимум 8 дочерних измерений.
- Нет текста SQL, аргументов запросов, IP, имени пользователя, cookie, полного URL, referer и user-agent.
- SQLite — единственный процесс записи; таблица корней и отдельная таблица дочерних измерений, связанная внешним ключом с каскадным удалением.
- Техническое время SQLx включает сетевые операции и обработку ответа: это **не** показание времени исполнения SQL сервером PostgreSQL.
- При сбое хранилища заявляется потеря диагностических данных. Счётчики \`tor_trace_export_failed_total\` и \`tor_trace_export_dropped_total\` позволяют увидеть её. Секреты и входные данные не выводятся в журналы ошибок.
- Данные, ранее чем TTL, могут находиться в свободных страницах SQLite до физической очистки файла; \`secure_delete=ON\` снижает риск остаточного чтения. Журнал отката может временно увеличить общий расход диска сверх ограничения основного файла.

## Установка на отдельном испытательном сервере

1. Собрать бинарный файл \`cargo build --release -p tor-observability --bin tor-trace-store\` вместе с сервером \`tor-web\`.
2. Установить \`ops/tor-trace-store.service.example\` как отдельную службу; **не активировать автоматически**. Она использует выделенного системного пользователя \`tor\`, закрытые каталоги состояния и сокета.
3. После проверки владельцев, прав и доступного диска запустить сервис. Для \`tor-web\` под тем же пользователем задать \`TOR_TRACE_STORE_SOCKET=/run/tor-traces/traces.sock\` и перезапустить сайт.
4. На испытательном сайте создать несколько обычных и ошибочных запросов, убедиться в росте \`tor_trace_export_sent_total\`, проверить \`report\`, затем перезапустить писатель и повторить чтение архива.
5. При выключении службы или переполнении очереди сайт должен продолжать отвечать; у экспортёра должны расти счётчики потерь, а в архив не должны попадать данные пользователей.

**Не выставлять** \`TOR_TRACE_STORE_SOCKET\` в среде рабочего сайта до проверки службы и разрешений. Изменения настроек сервера и выпуск требуют отдельного подтверждённого шага.

## Приёмка и ограничения первого участка

\`cargo test -p tor-observability --all-targets\`, \`cargo test -p tor-web --all-targets\`, \`cargo clippy --workspace --all-targets -- -D warnings\`, \`cargo fmt --all -- --check\`. Отдельный тест должен поднять настоящий процесс с Unix-сокетом, проверить повреждённый пакет и сохранение в SQLite. После перезапуска поиск старой трассы должен работать; TTL и ограничение количества удаляют и дочерние измерения.

Не готово: графическая страница администратора, агрегирование по нескольким серверам, доказательство развёртывания на VPS и автоматическая проверка пределов диска с учётом временного журнала.
