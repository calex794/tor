# MOD-OPS-ALERT-01 — приватный список просроченных заявок

Статус: самостоятельный продуктовый этап #661; не является push/email и
не включает автоматическую доставку. Требует схему из #664 (только в
изолированном CI, миграции постоянных БД не раскатывать).

Модератор сайта или администратор открывает `/moderation/books/alerts` из
кабинета регистрации. На экране находится не более 40 записей и ссылка на
следующую страницу. Для каждой заявки показывается только более высокий
активный порог (72 часа вместо дубля 24 часа), тип, идентификатор заявки,
ревизия, UTC-время первой фиксации и переход к соответствующей **закрытой**
очереди. Отдельные имя автора, книга, текст жалобы, причина отказа и S3
staging-ключ не отображаются. Сами числа 24/72 часа пока не приняты как SLA.

## Защита

- GET без сессии: 401; обычный пользователь: 403. Сервер и репозиторий
  независимо проверяют живую роль модератора сайта / администратора.
  Модератор только внутри команды книги не получает право.
- Репозиторий блокирует действующую роль/сессию до завершения чтения.
  При отзыве site-role последующий запрос закрывается.
- Сигнал отфильтровывается **до** LIMIT 40, если исходная заявка уже
  одобрена, отклонена, заменена, удалена или больше не ждёт решения.
  Список не опирается только на `signal_state='open'`.
- Для удаления учитываются точная ревизия и запрет рассматривать
  собственную книгу модератора.
- HTML — приватный `no-store`, `noindex,nofollow`, без запросов к
  публичному CDN или внешнему провайдеру.
- Переходы состоят только из серверно определённых безопасных маршрутов
  и константных фильтров. Непроверенная строка из базы не создаёт URL.
- Экран только читает данные. Он не отмечает доставку, не принимает
  модераторских решений, не подтверждает SLA и не отправляет сообщений.

## Приёмка

Реальный PostgreSQL/HTTP тест проверяет тройку заявок (регистрация,
обложка, удаление): пять пороговых записей сворачиваются в три
действующих элемента, доступ есть у независимого модератора сайта,
нет у владельца без site-role, отрицательный курсор отвергается.
После отзыва роли доступ отсекается. После снятия заявок с рассмотрения
они исчезают даже если событие ещё не было сверено наблюдателем.

## Ещё не реализовано

- Утверждение SLA, часов и политики эскалации.
- Выбор получателей и каналов, роль дежурного.
- Отдельная доставка с подтверждением получения, retry/dedup и live
  проверкой роли адресата прямо перед отправкой.
- Новые timestamp/revision для повторной регистрации книги.

Наличие приватного списка не означает, что кто-то получит
уведомление без входа в кабинет. Production/VPS/постоянные базы не менять.
