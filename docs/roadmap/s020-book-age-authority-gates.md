# S020 — возрастной уровень книги: достоверность и границы реализации

## Проверенный источник

- [NEwBOO `book_access_policy.py`](https://github.com/HeisLuka/newboo/blob/17125ef758a791e9630505c14d24f7fe65aed228/backend/app/books/policies/book_access_policy.py): пользователь без входа читает только `basic`; для `adult` нужен сохранённый `adult_enabled`, для `pro_adult` — действующий серверный grant.
- [NEwBOO `books_settings.py`](https://github.com/HeisLuka/newboo/blob/17125ef758a791e9630505c14d24f7fe65aed228/backend/app/web/routes/books_settings.py): редактор не понижает уровень книги, а переход на `pro_adult` впервые требует личного допуска.
- Модератор сайта — отдельная роль. Книжный модератор вправе работать только с конкретной книгой; никакой глобальной модерации это не даёт.

## Базовый слой B — в этом PR

- B использует уже существующий `books.access_level`, а не добавляет параллельный признак. Новые книги TOR явно создаются с `basic`; импортированные старые книги с `NULL` остаются **неаттестованными**. Они не могут быть молча приравнены к `basic` — это требуется в контракте B-09 передачи книги.
- `verified_upgrade_book_access_level` является **только внутренним методом `pub(crate)`**, без HTTP-роута, UI, изменения прав на чтение или публикацию. Доступен активному owner/translator/book moderator строго конкретной книги.
- В одной PostgreSQL-транзакции фиксируется порядок блокировок Book FOR UPDATE → BookMember FOR SHARE; устаревший `expected` получает Conflict; понижение уровня — Forbidden; `NULL` — Forbidden.
- Первое повышение до `pro_adult` требует активной записи `user_level_grants` у актёра и активного аккаунта. Оба ряда блокируются `FOR SHARE` до commit, чтобы отзыв гранта не конкурировал с записью.
- Никакая дата покупки, публикация, `visibility`, `lifecycle_status`, `project_status`, права на главы и финансы не переписываются.

## Блокирующее продолжение — НЕ считать S020 принятым

Прямое включение кнопки возраста сейчас небезопасно: `crates/reading/src/repositories/postgres.rs::public_chapter` и `public_book_page` не проверяют `books.access_level` и текущие факты пользователя. При переключении книги на 18+/21+ читатель без соответствующего допуска всё ещё мог бы получить текст через публичный reader.

До разрешения пользовательского изменения требуется доказанный PostgreSQL/HTTP E2E на **всех** read/discover/sale каналах:

1. Anonymous/basic не получает текст, книгу, TOC, карточки и предложения покупки `adult`/`pro_adult`; существующая раздельная административная читалка сохраняет свой законный доступ.
2. Логин пользователя не даёт `adult` автоматически; нужно `users.adult_enabled=TRUE`. Для `pro_adult` нужен действующий `user_level_grants` с проверкой в БД, без клиентских полей-авторизаций.
3. Применить gating атомарно при получении тела главы, включая бесплатные главы и pinned paid V1/V2, и проверить обходные API; нет права из progress/follow/library, нет изменения выданных покупок.
4. Интеграционные тесты: anonymous/basic/adult/pro_adult, revoked grant, held/deleted, admin, купленные версии, закрытые книги, гонки повышения и отзыва допуска.
5. После этого можно подключить B-команду к форме S020, проверить Origin/CSRF, RIL, браузер и post-merge CI на `main`.

## Независимая видимость

`books.visibility='draft'|'public'` сейчас отвечает за публикацию TOR. Нельзя выдавать эту пару за NEwBOO `visibility_status=active|hidden|pending_moderation|blocked`. Нужен отдельный контракт модерации и безопасного чтения, который сохраняет купленные версии и полномочия администратора. Смена `hidden` не равна отзыву доступа к купленным версиям; `blocked` — жёсткий отказ по политике NEwBOO.
