# A-09 / AB-03–AB-04: ловушки форм и адрес-ловушка

Реализация для текущей разработки в GitHub; сервер и постоянные базы не изменять.

- Форма входа и регистрации содержит невидимое обычное текстовое поле `website`. Оно исключено из навигации с клавиатуры и дерева доступности; нормальные пустые или отсутствующие поля не меняют действующий сценарий.
- Заполненное поле после проверки Origin/CSRF отклоняет запрос **до** обращения к учётной записи, Argon2, новому сеансу и записи в БД. Это подозрительный сигнал, не причина блокировать IP или жёстко запрещать аккаунт.
- `GET /__bp_honeypot/{*trap_name}` всегда возвращает пустой 404 с `Cache-Control: no-store`, `X-Robots-Tag: noindex, nofollow, noarchive` и `nosniff`. Маршрут не извлекает и не сохраняет содержимое пути, не читает БД, не пишет IP.
- Счётчики для `/metrics` имеют **только три фиксированных имени**, без email, IP, user-agent, названия ловушки или пути. Они служат диагностикой и не участвуют в решении об авторизации.
- Проверки: обычная форма с пустым полем; заполненные поля не создают регистрацию/сеанс; обычная регистрация и вход остаются рабочими; настоящий HTTP trap имеет пустой ответ; unit-тесты проверяют приватность и отсутствие необъявленного содержимого.

Граница: AB-02, AB-05 и AB-08–AB-14 (адаптивная защита, внешняя CAPTCHA, ограничение отдельных действий, ручные ограничения и защита от перегрузки) не реализуются этим изменением. Не считать всю систему AntiBot готовой.
