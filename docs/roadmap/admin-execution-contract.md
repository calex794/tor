## 1. Общий договор административной операции

1. Доступ выдаёт **один A: Actor/Permission** из подтверждённой сессии, не клиентский `user_id` или флажок HTML. Админский пользователь не получает неограниченный доступ к купленному телу главы вне отдельной разрешённой операции.
2. Чтение и изменение разведены: GET/диагностический JSON не изменяют БД и ничего не запускают; POST/PATCH требуют Origin/CSRF, явное назначение действия, роль, предел тела, журнал `actor+request_id+resource+action+result`. Команды с денежным/глобальным эффектом — атомарность и защита повтора через D/I `Idempotency-Key` или HTML `command_key`.
3. Согласованная таблица **`admin_action_audit`** (владелец I, запись через узкий контракт): `audit_id`, `actor_id`, `action`, `resource_type`, `resource_id`, `request_id`, `command_key?`, `before_revision?`, `after_revision?`, `outcome`, `occurred_at`; никакого тела сообщения, токена, платной главы, исходного IP или финансовых секретов. Запись действия делается в том же PG commit, где проходит соответствующая доменная команда; отказ и инфраструктурная ошибка фиксируются безопасно отдельно, без выдачи ложного успеха.
4. Владелец каждой бизнес-таблицы остаётся прежним. **H** создаёт HTML, **I** связывает маршруты, **A** проверяет роль; F/B/D/E/G владеют своей записью. H и I не реализуют второй сервис денег/рекламы/модерации.
5. Ошибки: 401 без сессии, 403 чужая роль, 404 скрытое/несуществующее по политике, 409 устаревшая редакция или несовместимый повтор, 422 неверные поля, 503 при недоступном достоверном состоянии. Диагностика отдаёт ограниченную выборку, счётчики и ошибки, **не** raw user/book/event IDs в публичной телеметрии; никакого полного сканирования таблицы на каждый просмотр.
6. **Отсутствие во вчерашнем реестре 69 S не снимает требования:** ADM-пункты являются дополнительными внутренними приёмочными опытами. Только после отдельного обновления реестров Notion и проверяющих скриптов увеличивать исторический счётчик S/F.

## 4. Порядок включения без задержки основного сайта

- **Д0:** I-02/I-05 и ADM-01 — зафиксировать список маршрутов, типы, таблицу аудита, ответственности.
- **Д1–Д3:** ADM-02/03/04 (права, справочники, новости); ADM-05/06 только как PG-транзакции и диагностические экраны без необоснованной платёжной активации.
- **Д4–Д5:** ADM-07…11 как независимые экраны и сервисы по существующим F/G/I/REC/RIL договорам. Не блокировать бесплатную читалку операторской аналитикой.
- **Д6–Д12:** ADM-12: пограничные и конкурентные PG/HTTP тесты, нагрузка, crash/restart, Chromium и видимость.
- **Бета:** любой недоказанный admin POST / финансовый контур скрыт за выключенным флагом. Read-only маршрут включается только с проверенной ролью, ограниченной выдачей и честным degraded статусом.

**Критерий «готово»:** не документ, не шаблон, не 200 от пустого JSON. Для каждой сохранённой операции: исходный Python путь → новый Rust use-case → таблица/проекция PG → реальная роль → успешный и запрещённый результат → повтор/отказ → подтверждение CI на последнем main SHA.
