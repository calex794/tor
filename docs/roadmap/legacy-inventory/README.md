# NEwBOO → TOR: машинная проверка HTTP и фоновых обработчиков

**Зафиксировано 26.10.2026.** NEwBOO: [`17125ef758a791e9630505c14d24f7fe65aed228`](https://github.com/HeisLuka/newboo/tree/17125ef758a791e9630505c14d24f7fe65aed228), TOR: [`sources.lock.toml`](../sources.lock.toml).

## Второй этап — назначение функционального смысла маршрутам

[Разметка всех 568 записей](route-action-candidates.tsv) создана 26.10.2026 после проверки [61 исторической функции](../functions-coverage-audit.tsv) и [117 задач](../tasks.tsv). **420** строк получили *кандидатную* группу F001–F061 (по модулю/маршруту/обработчику); **45** — дополнительные подфункции X-* с прямой ссылкой на задачи, **101** исключены, **1** Reader Boost отключён в legacy, **1** html revenue shares отсутствует в подключённом фасаде, хотя `PUT /api/v1/books/{book_id}/members/revenue-shares` доступен через API. Это **не** функциональная проверка 420 маршрутов и не работающий Rust: в каждой строке `verification=not_behavior_verified`.

Из 45 дополнительных действий обнаружены **8 маршрутов персональной статистики по книгам/главам** (`X-AUTHOR-STATS`) и **2 маршрута ручного менеджера источников** (`X-PROJECT-MANAGER`), которые не имели самостоятельной пооперационной приёмки среди 61 F / 69 S. Полный готовый [договор AUTHOR-01…08](../author-workspace-execution-contract.md) назначает владельцев и тесты. Ручной подсчёт `total_chapters` не использует URL crawler и **не размораживает** F021/S024. Остальные X-* уже привязаны к [ADM](../admin-execution-contract.md) / [AE](../domains-a-e-parity-2026-10-26.md), кроме сводной панели аккаунта в H-03.

**Предел:** это полноценное извлечение декораторов из 150 типичных файлов API/Web, анализ `main.py`, известных фасадов и реестра durable jobs **на закреплённом SHA**, но не запуск Python-приложения и не динамическая трассировка всех `add_api_route`/фабрик/отложенных флагов. Не выдавать результат за «все фактически доступные URL продакшена» или готовый Rust. Сценовые фабрики исключены по решению владельца, не реализовывать их ради полноты статистики. Дополнительные динамические регистрации, ещё не учтённые статическим обходом, должны попадать в новый снимок отдельно.

## Что делает проверка теперь

- [`http-route-coverage.tsv`](http-route-coverage.tsv): каждый обнаруженный HTTP handler с файлом/строкой, методом, возможным подключением, владельцем и требованием смысловой сверки.
- [`deferred-jobs.tsv`](deferred-jobs.tsv): все 65 зарегистрированных deferred имён + решение о заморозке и направление реализации.
- [`startup-schedulers.tsv`](startup-schedulers.tsv): 8 самостоятельных механизмов запуска, не смешаны с регистрацией deferred.
- [`mount-context.json`](mount-context.json): зафиксированы корневые роутеры и списки подключаемых endpoint трёх фасадов. `routes-part-*.tsv` — воспроизводимый снимок 150 исходных файлов.
- [`tools/check_legacy_coverage.py`](../../../tools/check_legacy_coverage.py): для каждой правки в TOR проверяет закреплённый SHA, наличие всех исходных элементов, непротиворечивость подключения, явные исключения, единый реестр заданий и поведение отрицательных проверок. Приоритет — **не потерять сведения**. Обычная проверка допускает `semantic_review` с честным отчётом; `--strict` **должна падать** до действительной ручной смысловой приёмки.
- [`tests/architecture/test_legacy_coverage.py`](../../../tests/architecture/test_legacy_coverage.py): проверки специально портят входные данные и требуют обнаружения исчезновения маршрута, неправильного SHA, снятия заморозки или исчезновения обработчика.

**Что остаётся для буквального доказательства 100%:** пройти 443 смысловых сопоставления не на совпадение URL, а на действие пользователя/право/данные и убедиться в работающем PostgreSQL/HTTP/Chromium на новом TOR. Успех проверки снимка не утверждает полноты продукта. Не начинать реализацию обнаруженных спорных функций без утверждённого объёма.
