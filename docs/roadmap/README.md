# TOR — рабочая дорожная карта 15 дней: 117 строк задач, 69 сценариев

**Цель этой папки:** исполнитель получает источник кода, задания, выбранные контракты и приёмочные испытания. **Проверка 26.10 выявила, что 117 заголовочных задач покрывают 69 сценариев по названию, но не полностью специфицируют 61 историческую функцию.** Перед опасными предметными ветками обязательны уточнения из [аудита полноты](preflight-audit-2026-10-26.md); не выдавать документационное покрытие за реализацию. В **main** TOR 25.10.2026 только S0 **in-memory демонстрация**, поэтому все новые HTTP/PG/commerce действия являются **работой**, а не уже запущенным сайтом.

## Календарь с конкретными зависимостями

### Д0 — 25 октября: подготовка перед переносом
**I-01/I-02**: закрепить `tor/main`, источник NEwBOO и bokarust; добавить `tor-contracts` с выбранными Actor/BookId/ChapterVersionId/Entitlement/Event схемами. **A-01/B-01/C-01/D-01/E-01/F-01/G-01/H-01** уже имеют решения в этой папке; исполнители **не проводят отдельное исследование**, а переносят типы/правила, сразу фиксируя tests. Исторические S/F ссылки лежат в `scenarios.tsv`.

### Д1 — 26 октября: настоящий PG-сайт, а не RAM-декорация
**I-03/I-04/I-05**: адаптировать проверенные SQLx миграции 001–009 и реальный browser-box; в TOR поменять `readyz` (сейчас псевдоготовность) на `SELECT 1` и migration gate. **B-02/B-03, F-02, C-02, H-02**: каталог → книга → реальная опубликованная глава из PostgreSQL. **A-02/A-03**: реальные users/sessions. **G-02**: начальный импорт статуса. День заканчивается *фактическим Chrome+PostgreSQL* и перезапуском, без фиктивных пользователей.

### Д2 — 27 октября: полный авторский и читательский путь
**A-04/A-05** Actor и роли; **B-04/B-05** immutable version/draft; **C-03/C-04/C-05** 501 chapter cursor и free progress; **F-03/F-04** поиск/витрина; **H-03/H-04/H-05** формы входа/редактора/читалки; **I-07** дешевый CI selector с fail-safe broad для общего. Без DB или без отрицательных проверок ничего не считается готовым.

### Д3 — 28 октября: платный цикл
**B-06/B-07** публикация/outbox+расписание; **D-02/D-03/D-04/D-05** wallet/ledger/grant/batch/layer; **C-06/C-07** paid progress BKR-134 и paywall; **G-06/G-07** outbox/lease; **H-06** покупка. End-to-end: автор выпустил V1 → читатель купил → V2 → вернулся к V1/P; одновременная двойная покупка списывает один раз.

### Д4 — 29 октября: вторичные функции параллельно
**B-08…B-13** команда, доли, приватные книги; **E-02…E-12** комментарии/клубы/подписки/поддержка; **F-05…F-12** SEO/recommendations/referrals/ads (раздача disabled до доказательства); **G-03…G-10** импорт, изображения, уведомления; **H-07…H-11** соответствующие формы. Внешние интеграции с отсутствующим договором — feature flag OFF, без подмены успешным тестом.

### Д5 — 30 октября: интегрированная версия-кандидат
**B-15/B-16, C-11/C-12, D-12/D-13, E-13/E-14, F-13/F-14, G-11/G-12, H-12, I-08/I-12/I-13**. Последний допуск — у каждой *включённой* S записи есть реальный код/PG/HTTP/браузер + отказ либо записанный блокер; заглушки не проходят. После merge обязателен контроль на **новом** main SHA.

### Д6–Д7 — 31 октября – 1 ноября: реальные данные
Миграции fresh и upgrade, FK, уникальность, стоимость запросов, 501 глава, выдача платных прав, тайминги очереди; 16 P0 исторических сценариев пересмотреть с учётом `S041` внешнего блокера.

### Д8–Д9 — 2–3 ноября: поведенческий паритет
На одинаковых книгах/ролях/версиях последовательно проверить реальные браузерные сценарии Rust против исходного NEwBOO. Пустые, скрытые и платные ответы проверяются как отрицательные. Зафиксировать каждое **разрешённое** изменение поведения отдельной строкой в Notion, а не молчаливым «похожим результатом».

### Д10–Д11 — 4–5 ноября: неприятные сценарии
Двойные покупки, плохой интернет, отмена worker, параллельная публикация, stale save, неожиданный отказ PostgreSQL/объектного хранилища, отзыв прав посреди запроса, retry после commit, мошенническая реклама и утечки через preview/notifications.

### Д12 — 6 ноября: кандидат беты
Полная цепочка Cargo+PG+Chromium+backup-restore+rollback на едином SHA, красное P0 = не выпускать. Задокументировать фактическое время CI/очереди, CPU/RAM и неисправленные S.

### Д13–Д15 — 7–9 ноября: ограниченная бета и решение
HTTPS/отдельная PostgreSQL/бэкапы; три роли (читатель/автор/админ) в реальном браузере; опциональная реклама/OAuth/Boosty выключена до доказательств; финальная матрица со всеми S/F и точным SHA. В 15-й день **решение о выпуске**, не автоматическая декларация 100%.

## Междоменные зависимости, которые исполнитель не должен разбирать заново

```text
I: contracts + migration release + web composition
                  |
         +--------+-----------+
         v                    v
     A Actor                  B Book/ChapterVersion/Publish
         |                    |          |
         +----> D Entitlement <+          +--> G Outbox/Delivery
         |         |                          |           |
         +-------> C Reader/Progress <--------+--> E Inbox / F Search
                                                   |
                                                   v
                                               H SSR pages
```

Книгу/главу пишет только B, баланс/деньги — только D, прогресс — только C, пользовательские сообщения — только E, производную выдачу — только F, доставку — G. I предоставляет механизмы и не подменяет предметные решения. Исключение — согласованный insert события в общий outbox в **той же** транзакции владельца бизнес-факта.

## Контроль сходимости

- **Одна задача**: проходит целевая функция теста, в PR приложены source URL, выходной SHA, связанный S, проверка и отрицательный случай.
- **Одна предметная ветка**: все связанные задачи написаны, после чего проведён **пакет** её тестов, общие причины падений исправлены, весь предметный пакет повторён на окончательной версии.
- **Весь проект**: никакие девять зелёных пакетов сами по себе не дают green main; I проверяет сквозные цепочки на итоговом SHA. Исходная матрица выполнения Notion остаётся единственным реестром статуса.
