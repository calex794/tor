# E-11 / S050–S051 — поддержка гостя и пользователя

Статус: реализация в рабочей ветке; окончательная приёмка Rust/PostgreSQL/Chromium
фиксируется по точному SHA. Это не завершение всей линии E и не обновление сервера.

Источник: NEwBOO `17125ef758a791e9630505c14d24f7fe65aed228`:

- `backend/app/support/services/support_chat_service.py`: отдельная переписка
  поддержки, 4000 Unicode-символов, plain text, client ID до 128, страницы 100/200.
- `backend/app/support/repositories/memory_support_chat_repository.py`:
  объединение гостевой истории с уже существующей историей учётной записи.
- `backend/app/support/services/support_claim_service.py`: не хранить сырой
  гостевой ключ в базе и в отложенных заданиях.
- `backend/app/web/routes/support.py`, `admin_support.py`: widget/messages,
  очередь администратора, ответ/прочтение и текущая глобальная роль.
- `backend/app/services/action_rate_limit_service.py`: неизвестный scope
  `support_message` становится `default`, исходные значения 120/60 за минуту.

Реализовано: `tor-support`, отдельные таблицы поддержки, HTML `/support`,
совместимые GET `/support/widget`, GET/POST `/support/messages`, административные
страницы/получение сообщений/ответ, JSON GET/POST `/api/v1/support/tickets`.
Вся запись через один сервис и PostgreSQL-репозиторий. В JSON только `{message}`;
43-символьный Idempotency-Key, Origin и X-CSRF-Token обязательны, чужой payload
с тем же ключом даёт 409. HTML сохраняет исходную семантику receipt.

Гость получает HttpOnly/SameSite=Strict/Path=/ cookie из случайных 256 бит;
в HTTPS используется __Host- и Secure. База хранит только SHA-256 с разделением
назначения `tor-support:`. Техническая адаптация исходного HMAC: исходный материал
уже криптографически случайный, отдельного конфигурационного секрета для запуска
не требуется; это не хеш предсказуемого ID и не токен из параметра URL.

На первом открытии/отправке после входа локальная PG-транзакция объединяет
гостевую историю с прежним диалогом пользователя и погашает ключ. Повтор того
же пользователя безопасен; другой аккаунт и прежний анонимный ключ получают
отказ. Сырой ключ не попадает в БД, журнал или исходящую очередь. Отдельное
сетевое задание для одного локального атомарного объединения не требуется.

Истёкшая гостевая история немедленно недоступна; ограниченная почасовая очистка
удаляет её с сообщениями. У привязанной истории нет гостевого TTL. Таблица
support_guest_claims препятствует переназначению уже использованного ключа.

Административные GET не записывают состояние, согласно более строгому ADM-01:
вместо исходной GET-записи отметка прочтения выполняется отдельным POST с CSRF.
Ответ и изменение отметки имеют общий append-only admin_action_audit в той же
транзакции. Повтор ответа сохраняет один исходный Message и одну запись аудита.
В аудит не записываются текст, гостевой ключ, IP или клиентский ключ сообщения.
Каждый HTTP/poll/POST заново проверяет действующую A-сессию и administrator,
автор/модератор книги не получают операторский доступ. Список ограничен 100,
имена пользователей разрешаются одной пакетной A-операцией.

Проверки: PG повтор/8 отправителей/гонка claim/перезапуск/слияние историй/
203 сообщения/TTL/административные полномочия; HTTP Origin/CSRF, запрет чужого
claim, отзыв роли, JSON strict idempotency; Chromium 390/1440: гость → сообщение →
вход → сохранённая история → оператор → ответ → пользователь, XSS и ширина.

Перенесены исходные support-widget.js/CSS и admin-support.js с сохранением
ленивого открытия и 5-секундного polling. Исправлены совместимость multipart→
URL-encoded для Axum и повтор с тем же client ID после сетевой ошибки; исходный
текст в error-state сохраняется. Виджет скрыт до запуска своего скрипта, поэтому
строгий CSP остальных личных страниц не ослаблен: там остаётся ссылка на /support.
На самих страницах поддержки разрешены только локальные скрипты/соединения.
Полная страница доступна без JavaScript. Браузерный опыт начинает гостевое
обращение именно через исходный плавающий виджет, затем продолжает после входа.

Остаётся отдельно: фоновая доставка уведомлений операторам в общий центр
уведомлений G; очередь поддержки и её независимый unread уже долговечны в PG.
Внешняя почта не имитируется. Эти различия не выдаются за полный интерфейсный
паритет всего NEwBOO. Никаких платёжных действий.
