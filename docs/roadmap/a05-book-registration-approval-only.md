# A-05 — только модерация регистрации книги

**Правило продукта (4 ноября 2026):** модератор определяет доступ книги на сайте
при регистрации. **Каждая отдельная глава НЕ проходит модерацию.**
Перенос MOD-C01/C02/C03 в TOR признан ошибочным расширением функциональности.

## Сценарий

1. `create_owned_book` сохраняет `books.visibility='draft'` и
   `books.visibility_status='pending_moderation'`.
2. Модератор или администратор решает судьбу книги через
   `/moderation/books`: `active`, `hidden`, `pending_moderation`, `blocked`.
   Решение фиксируется в неизменяемом журнале с CAS-ревизией.
3. Авторская `books.visibility='public'` и решение модерации независимы.
   Публичное чтение доступно только при `active`, `public` и без удержания.
4. После одобрения книги её участники публикуют новые бесплатные и платные
   главы без модератора. Остаются авторские права, проверка версии и,
   для платных глав, B/G S3-шифрование, проверка, подписи и права покупателя.

## Удалённые полномочия

`GET /moderation/chapters` и `POST /moderation/chapters/{id}/hold`
отсутствуют. Удалены очередь, модераторские `hold/hide/block/publish/draft`
для отдельных глав, обработчики, тесты и регистр RIL этих маршрутов.
Никакой отдельной «публикации платной главы модератором» не требуется.

Исторические миграции и append-only записи MOD-C01/C02/C03 сохранены.
Схема не удаляется до отдельного аудита: сохранение журналов предпочтительнее
уничтожения данных. Уже существующее `chapters.admin_hold` остаётся
legacy-ограничителем чтения, а не механизмом одобрения новой главы.

## Аудит остаточных блокировок глав (read-only)

`chapters.admin_hold` возник в [BKR-86](../../migrations/202610120004_public_reading.sql),
ещё до MOD-C01/C02/C03. Впоследствии MOD-C02 добавил
`chapters.moderation_state` и триггер синхронизации. PR #501 удалил
административные HTTP-маршруты для глав, но сознательно не удалил
исторические ограничения доступа и журналы.

Скрипт [a05-retired-chapter-holds-read-only.sql](../audits/a05-retired-chapter-holds-read-only.sql)
содержит только запросы в транзакции `READ ONLY`. Он показывает агрегаты
по состояниям, книги с оставшимися блокировками и не более 100 идентификаторов
глав с числом действующих библиотечных записей и исторических покупок.
Скрипт не снимает блокировки и не переносит их автоматически на книгу:
это может необоснованно расширить доступ или заблокировать всю книгу.

**Граница знания:** тестовая база CI не доказывает отсутствие блокировок
в постоянной БД. Этот аудит не запускался на production/VPS; без проверки
данных нельзя утверждать, что `admin_hold=TRUE` нигде не осталось.
При обнаружении записей требуется отдельное решение по книге и сверка
читательских прав; автоматическое `UPDATE chapters SET admin_hold=FALSE`
запрещено.

## Приёмка

- Новая книга остаётся `pending_moderation` и скрыта до решения модератора.
- Одобрить книгу может только действующая роль с CSRF и проверкой ревизии.
- Следующая глава выпускается автором после допуска книги без повторной модерации.
- Старые маршруты модерации глав возвращают 404; RIL их не знает.
- Платный E2E и сохранность прав покупателя не затронуты.
