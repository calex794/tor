# TOR — кабинет автора: статистика книги и ручной учёт глав (AUTHOR-01…08)

**Результат смысловой сверки 26.10.2026.** Это детализация **B-14 + F-12 + H-07 + G-10 + I-12**, а не десятая рабочая линия и не новый план сборщика. Эти функции подтверждены исходными маршрутами NEwBOO, но **не были пооперационно выделены среди 61 исторической функции / 69 пользовательских сценариев**. Результат зафиксирован в [маршрутной карте](legacy-inventory/route-action-candidates.tsv) как `X-AUTHOR-STATS` (8 маршрутов), `X-PROJECT-MANAGER` (2 маршрута). **Ни одна возможность не считается реализованной в TOR.**

**Исходная ревизия:** [NEwBOO @ 17125ef758](https://github.com/HeisLuka/newboo/tree/17125ef758a791e9630505c14d24f7fe65aed228).

## Исторические доказательства и границы

- [api/v1/book_stats.py](https://github.com/HeisLuka/newboo/blob/17125ef758a791e9630505c14d24f7fe65aed228/backend/app/api/v1/book_stats.py): защищённый доступ активного участника/владельца книги, пять GET-срезов — `/books/{id}/stats`, `/stats/dashboard`, `/chapters/stats`, `/stats/daily`, `/chapters/{id}/stats/daily`. Предел даты **366 дней**, `top_limit` **от 1 до 50**, `date_from ≤ date_to`, проверка принадлежности главы книге.
- [web/routes/books_stats.py](https://github.com/HeisLuka/newboo/blob/17125ef758a791e9630505c14d24f7fe65aed228/backend/app/web/routes/books_stats.py): HTML `/books/{book_ref}/stats` и экспорт `/stats/export.csv`; есть таблица показателей, главы и финансовые колонки `author_net_revenue`; CSV должен быть безопасен для открытия в табличном редакторе.
- [web/routes/my_books.py](https://github.com/HeisLuka/newboo/blob/17125ef758a791e9630505c14d24f7fe65aed228/backend/app/web/routes/my_books.py): GET/POST `/me/books/project-manager`; [view_models/my_books.py](https://github.com/HeisLuka/newboo/blob/17125ef758a791e9630505c14d24f7fe65aed228/backend/app/web/view_models/my_books.py) показывает **ручное** количество глав в источнике, количество опубликованных глав, список собственных книг и связанную рекламу. POST сохраняет `total_chapters` только своих книг; обновление в legacy идёт по одной книге.
- **Функция не является сборщиком книг.** Показ/ручной ввод количества глав из источника **не требует** обхода URL, запроса удалённого каталога и импорта текста. **F021/S024/G-03 полностью заморожены**, как и любые crawler API, scanner/cron и парсеры сайтов. Если требуется сторонний URL, он только метаданные уже существующей книги и не запрашивается сервером.

## Отнесение к существующим планам

- `X-AUTHOR-STATS` → B-14/F-12/H-07/G-10/I-12, отдельная проверка для автора; **не смешивать** с аналитикой команды F023/S029.
- `X-PROJECT-MANAGER` → B-02/B-14/H-07, **не** F021/S024: только ручные данные.
- `X-ACCOUNT-DASHBOARD` → H-03/A-06/F-04 (общая панель), не отдельный источник истины.
- `X-REVENUE-HTML` → B-10/D-08/H-04; HTML route не смонтирован, **но** в NEwBOO есть рабочий по исходному подключению `PUT /api/v1/books/{book_id}/members/revenue-shares`. Не писать вторую команду.
- `X-NEWS` и `X-ADMIN-TEAMS` уже описаны в [ADM](admin-execution-contract.md), не создавать дубль.

**Статус:** подробная спецификация. Никакой реализованной функции Rust из этого документа не следует. [Машинная карта](legacy-inventory/route-action-candidates.tsv) является **кандидатной трассировкой**, а не доказательством поведения. Для каждого AUTHOR-подшага обязательно исходный Python-метод → владелец Rust → PG/HTTP тест → итоговый коммит.
