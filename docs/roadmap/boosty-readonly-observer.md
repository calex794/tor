# TOR D-10/S041 — чтение событий Boosty без начислений

**Статус:** самостоятельный исследовательский инструмент владельца проекта. Не часть работающего сайта и не доказательство поступления денег.

## Что делает

- Доступ к строго одному адресу: https://api.boosty.to/v1/blog/stat/{blog}/events (метод GET, фильтр subscribe,recurrent).
- Ограничивает размер ответа (1 МиБ), число страниц (до 5), запрещает перенаправления, прокси и небезопасные символы имени блога.
- Показывает тип события, время, непересчитанное поле суммы, наличие плательщика и короткие контрольные отпечатки предполагаемых идентификаторов.
- Не выводит почту, имена, числовые идентификаторы подписчиков, полные идентификаторы событий или токен.
- Не подключается к PostgreSQL, не зачисляет деньги и не вызывается из tor-web.

## Как запустить локально

Использовать только собственный авторизованный токен владельца блога Boosty, не публиковать его и не пересылать в чат. Поместить токен в переменную окружения TOR_BOOSTY_PROBE_TOKEN через закрытое хранилище или защищённый локальный файл (не писать сам секрет в командную строку или репозиторий).

Затем выполнить следующую команду в каталоге проекта:

    cargo run -p tor-commerce --bin boosty-events-probe -- --blog MY_BOOSTY_BLOG --limit 50 --max-pages 3

Токен используется только для текущего сеанса. Инструмент не продлевает токены. HTTP 401 означает отсутствие действующей авторизации; не обходить её.

## Что нужно установить по настоящим операциям

1. Действительно ли subscribe означает первоначальную оплату, а recurrent — отдельное оплаченное продление.
2. Есть ли у каждой операции неизменный уникальный идентификатор **денежного списания**, а не статус подписчика, снимок события или накопленная сумма.
3. В какой валюте и единицах возвращается amount, и как учитывается комиссия Boosty и isFeePaid.
4. Когда событие подтверждает поступление денег; пробные и подарочные подписки исключить.

Пока нет ответов, никакой VerifiedSubscriptionCharge из события не создаётся. Нельзя использовать контрольный отпечаток события как идентификатор платежа. Возвраты по принятому решению контролируются вручную.

Основа: NEwBOO backend/app/external_payments/providers/boosty_probe_client.py и https://github.com/beekamai/boosty-api/blob/main/src/resources/stats.ts. Boosty API не является подтверждённым стабильным финансовым интерфейсом.
