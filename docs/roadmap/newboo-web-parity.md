# TOR H — восстановление пользовательского интерфейса NEwBOO

**Источник истины:** [NEwBOO `backend/app/web`](https://github.com/HeisLuka/newboo/tree/17125ef758a791e9630505c14d24f7fe65aed228/backend/app/web), `main` на `17125ef758a791e9630505c14d24f7fe65aed228` (20.09.2026). В каталоге `web`: **883 записи (включая каталоги), 177 HTML-шаблонов**. Дизайн переносится, а не разрабатывается заново.

## Критическая ошибка первого переноса

В TOR базовый макет был заменён собственной зелёной темой, простой шапкой и пустым футером, а поиск/каталог/читалка получили упрощённые HTML вместо многофайловой системы NEwBOO. Это **не визуальный паритет**, даже если PostgreSQL и маршруты исправны. Пустой каталог после запуска PostgreSQL также не подтверждает перенос книжных данных.

## Обязательная приёмка

1. Снимки 1440 и 390: главная, каталог, карточка, регистрация, кабинет, читалка. Сравнивать **рядом с оригинальным NEwBOO**, а не только с предыдущим TOR.
2. Браузер: оригинальное фирменное изображение доступно по `/assets/brand/pandaolate-header.png`; общие цвета/классы действительно загружены, меню открывается на мобильном, нет горизонтальной прокрутки.
3. PostgreSQL/HTTP: настоящая публикация → каталог → книга → свободная глава; приватная книга не выводится; никакой имитации рейтингов или примеров с незавершённой публикацией.
4. Известные незавершённые блоки описывать в виде реестра несоответствий. **Частичный видимый результат не равен 100% NEwBOO.**
5. Не трогать пользователю рабочий VPS до успешных проверок соответствующего PR и безопасного переключения. Никаких неутверждённых миграций и тестовых книг в продуктивной БД.

## H-web-07 — перенос системной тёмной темы

- Источник: [NEwBOO `00-tokens.css`](https://github.com/HeisLuka/newboo/blob/17125ef758a791e9630505c14d24f7fe65aed228/backend/app/web/static/css/00-tokens.css), `:root[data-theme="dark"]`; оба оригинальных логотипа `pandaolate-header*.png` уже перенесены побайтно в TOR (PR №76).
- Реализован первый этап без JS: при системной настройке **тёмная тема** используются исходные цвета `#0b1120` / `#111827` / `#f8fafc` / `#8b9cff`, настоящий `pandaolate-header-dark.png`, тёмные поля, панели кабинета, карточки, страницы книги/читалки и страницы ошибок. При светлом режиме остаётся оригинальный светлый вариант и обычный логотип.
- Реальная браузерная приёмка на 390 и 1440 пикселях охватывает главную, каталог, книгу, бесплатную главу, регистрацию и конфликт регистрации; снимки обоих режимов прикрепляются к Actions. Проверяются смена предпочтения назад, отсутствие горизонтального переполнения и неизменные HTTP-маршруты.
- **Не заявлять полный визуальный паритет:** оригинальная ручная кнопка `data-theme-toggle` из `theme-toggle.js` пока не перенесена: в TOR действует строгая политика `script-src 'none'`. Для ручной настройки требуется отдельное согласованное решение, не ослабляющее CSP, либо переключатель на сервере.
- Ни сохранение темы, ни персональные рекомендации, ни покупка главы этим изменением не появляются. VPS меняется только после всех проверок и отдельной операторской приёмки.

## H-web-09 — реальные проверенные обложки (PR №103)

- Шаблоны оригинальных BookCard/главной/книги показывают изображение только при наличии B-owned текущего проверенного варианта в PostgreSQL. Непроверенные книги, черновики, заблокированные и удалённые не получают даже адрес `/covers/{id}/...`.
- Новые HTTP-маршруты `GET /covers/{id}/card.webp` и `GET /covers/{id}/main.webp` возвращают реальные WebP **только после** B-проверки публикации и владельца, GET из закрытого S3, проверки размера, SHA-256, сигнатуры RIFF/WEBP и повторной B-проверки после I/O. Ни ключ объекта, ни bucket не выдаются клиенту.
- Для ответов с картинками и ошибок применяется `Cache-Control: no-store`, `X-Content-Type-Options: nosniff`, `script-src 'none'`. Пределы чтения: 8 MiB, 8 секунд, до 6 одновременных запросов на процесс. При проблемах с S3 — 503 с пустым телом, при отзыве доступа — 404. Для книг без обложки остаётся «Нет обложки».
- Подключение к реальному S3 включается **только оператором**: собрать `cargo build -p tor-web --release --features s3-covers`, настроить AWS SDK (регион, учётные данные/роль, адрес S3-совместимого сервиса) и `TOR_COVER_S3_BUCKET` для непубличного бакета. Без переменной бакета интерфейс сохраняет существующее поведение; переменная при сборке без функции приводит к ошибке старта. На VPS и в производственной БД ничего автоматически не меняется.
- Проверки: тесты реального PostgreSQL с имитацией S3, создание и замена настоящего WebP, проверка HTTP, защита от испорченного объекта, публикация/отзыв прав, экранирование HTML. **Отдельно обязательно:** тест с реальным S3-совместимым поставщиком, перенос книжных данных/медиа, сравнение скриншотов с исходным NEwBOO. Без этого не заявлять полный перенос медиа или готовность к выкладке.

## H-web-10 — приёмка S3-совместимого хранилища без доступа к VPS

- Отдельный изолированный MinIO на `127.0.0.1` в GitHub Actions. Версия сервера закреплена. Тест создаёт только временный бакет `tor-private-cover-ci` со встроенными тестовыми учётными данными и не подключается к рабочему S3 или PostgreSQL.
- Настоящий AWS SDK (включая подпись запросов) выполняет PUT → HEAD → GET одного небольшого WebP. Проверяются размер, SHA-256, повторная запись и отказ при неизвестном объекте, неверном ключе и выходе за ограничение размера. Прямая анонимная загрузка объекта должна вернуть HTTP 403.
- Подмена объекта с сохранением правдоподобных HEAD-метаданных специально показывает границу ответственности: HEAD недостаточно для проверки содержимого, поэтому `CoverDelivery::read` обязан повторно вычислять SHA-256 после GET. Это уже проверяется отдельно в PostgreSQL+HTTP-тесте H-web-09.
- В CI это не замена проверки полномасштабной миграции книжных обложек с NEwBOO, производственного S3 и безопасности его конфигурации. Реальная выкладка, изменение бакета и перенос медиа запрещены без отдельной приёмки.
