# Правила агентов tor

1. **Единственная цель:** перенести поведение текущего NEwBOO в один Rust/Axum + PostgreSQL сайт. Не делать новую архитектуру ради архитектуры. Использовать работающий код bokarust после проверки источника.
2. **Девять линий:** A identity, B publishing, C reading, D commerce, E community, F discovery, G ingest/jobs, H interface, I integration/deploy. Работать только в назначенной области; для общих `Cargo.toml`, `lib.rs`, `routes.rs`, `main.rs`, контрактов и миграций подавать изменение интегратору I.
3. **Один main:** ветка на конкретный сценарий/группу, затем короткий PR; после слияния начинать на актуальном main. Никаких девяти финальных гигантских PR. Не делать прямой push в main после настройки правил защиты.
4. **Источник правил:** [Tela Wiki roadmap](https://telawiki.com/spaces/430/pages/7725/bookarust-main-100-newboo), [Notion contracts](https://app.notion.com/p/40432a84beec81c49bbad75e88ff6989), [NEwBOO scenarios](https://app.notion.com/p/40432a84beec8160b18ae1ef4bade732).
5. **Доказательство:** каждый PR содержит ID сценария, старое поведение, новое поведение, изменённые контракты, PostgreSQL тест, негативный случай, браузерный путь для UI, ссылку на SHA и CI. Код без фактического пути не готов.
6. **Безопасность:** закрытые черновики и платный текст не раскрывать. Атомарные транзакции денег, повторяемость, неизменяемая купленная версия, CSRF/Origin. При отсутствии права — отказ. Не ослаблять проверки ради зелёного CI.
7. **Скорость CI:** сначала быстрые тесты затронутых областей с учётом зависимостей. Для изменения общих типов, прав, финансов и SQL миграций — расширенный набор; полный прогон регулярно и перед выпуском. Не пропускать тесты по неизвестным зависимостям.
8. **Файлы:** цель до 400 строк, выше 600 запрещать через архитектурные проверки после их переноса; тесты предупреждать после 800, блокировать после 1000. Не создавать глобальные God modules.
9. **Фронтенд:** первое видимое приложение — HTML/CSS, выводимые Axum с настоящими данными. Не блокировать запуск экспериментами Leptos/FrontRust/WASM. Сложные части проверять отдельно; единые права на сервере.
10. **Развёртывание:** deploy только из успешно проверенного main и только после конфигурации защищённых secrets/runner и серверных прав. Никогда не помещать SSH ключи, пароли, токены и реальные пользовательские данные в GitHub. Не смешивать испытательную и производственную БД.
11. **Проверка результата:** браузер и реальная PostgreSQL, перезапуск, ошибки, конкуренция там где нужно. Документы не означают готовность.
12. **Область 100%:** исторические S053–S056 заморожены старым решением. Их включение для буквального полного соответствия требует явного решения; скрывать расхождение нельзя.

Обновлять статус в существующем Notion реестре, не создавать его копию.

## Обязательные технические границы (решение 25 октября 2026)

- **Чистовой код только в TOR**, bokarust — источник проверенных прототипов. Один репозиторий, один сервер и одна PostgreSQL.
- **Одна предметная область = пакет `crates/<feature>`**, внутри собственные `api/`, `services/`, `repositories/`, `schemas/`, `domain/` по необходимости и тесты рядом с областью. Не плодить пустые каталоги, но не оставлять бизнес-код в общем `src/`, `services/` или `repositories/`.
- **HTTP → service → repository → PostgreSQL**; HTTP не содержит SQL и бизнес-решений, сервис не импортирует SQLx, домен не импортирует Axum или SQLx. Прямые зависимости между соседними функциональными пакетами запрещены; междоменные интерфейсы через `crates/contracts`, связывание через `crates/web`.
- В `architecture/modules.toml` регистрируется единственный владелец каждой области. Изменения карты, типов контрактов, миграций и общего wiring согласуются с линией I.
- У пакета собственные тесты. Внутри цельной ветки сначала дешёвая компиляция, по завершении полный набор области, групповое исправление ошибок и повтор обязательного набора; общие, финансовые, ACL и неизвестные изменения расширяют испытания до зависимых областей. Проверки на финальном интеграционном SHA обязательны.
- **Не пытаться обходить `tools/check_feature_layout.py` и обязательный статус `Repository rules`.** Подробности: [docs/architecture/feature-first.md](docs/architecture/feature-first.md).
